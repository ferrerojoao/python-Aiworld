## 0. 一页纸摘要

**问题**：候选只能整体采纳；重掷是**从头再写**（`reroll` 不喂上一稿），所以"只不满某一段"原先无路可走。

**结论**：加**第四条路**——就地手改。不用新环节、不用新工位、不加新设置项；改动 = 一个端点 + 一次辅助模型调用 + 前端一个编辑态。

| 选项 | 判断 | 理由（玩家原话） |
|---|---|---|
| ① 局部重写（把不满那段喂回编剧） | ❌ 否 | 「为了重写一小段，编剧那一大段提示词又要重新输入一遍」——工作单整份重灌，不划算 |
| ② 指出不满、定向重掷 | ❌ 否 | 「现有功能完全能实现，只要不采纳直接放弃然后重输入就够了」 |
| ③ **就地手改**（本文） | ✅ **做** | 「算来算去可能只有手改划算一些」 |
| ④ 存成新候选版本 + 对比 | ❌ 否 | 「那样不直观，就直接就地改原稿就好了」 |
| ⑤ 界面上显示摘要变化 | ❌ 否 | 「界面也没必要显示摘要变了，后台变就行，本来前台输入的时候也是不看摘要的」 |
| ⑥ 骰子 / 对勾图标 | ❌ 否（**只换这两个**） | 「最好把骰子和对勾图标都改成文字，不然这里功能多了容易认不出」——⚠️ 当日补正：`◀ ▶` **保留图标**（方向自明，换成"上一稿/下一稿"只会把这一行撑长） |

## 1. 手改只有一个隐藏代价：摘要

手改本身很简单（把 `prose` 写回候选）。**难的是摘要**——它不能跟着一起被玩家改，也不能不管：

- 摘要**此后每轮都被压成一行重新装配**给编剧与导演（`workorder.event_log_block`：最近 3 条给全文，其余压成一行）。它不是"这一稿的注释"，是**长期记忆**。
- 于是陈旧摘要有两种坏法：① 与新正文不符 → 后续回合照着废摘要往下写；② 玩家刚删掉的私密信息继续被传下去 → **脱敏侧门**（与质检防的是同一件事，同源）。
- 但摘要**不可再分**：整场压缩，只有"整条不动 / 整条重算"两个值。所以判据只能是"**不一致才改**"。

这与质检里那条 `summary` 字段**是同一件事**，只是触发时机不同：那边是"质检改了正文"，这边是"玩家改了正文"。于是判据直接复用同一套措辞，实现上收窄成一个只回一句摘要的输出形状（`SummaryOutput`），避免顺手把"改后的正文"当成质检结果写回候选。

## 2. 位置：为什么在"保存手改"那一刻，不在采纳

```
写轮(可两段式) → 质检(可能改稿) → 候选落盘 →【手改 + 摘要核对】→ 采纳 commit → 此后每轮只吃摘要行
                      ↑ 摘要修正在这里发生        ↑ 摘要对齐在这里发生（本方案）
```

- **不放在采纳**：`Transaction.commit` 是原子提交区（审计 → 时间 → 事件 → 落盘 → 清候选），把一次可失败的 LLM 调用塞进提交路径，会让"玩家点采纳"变成一次网络赌注。
- **也不放在写轮**：手改发生在写轮之后，写轮此刻还不知道玩家会改什么。
- **候选的 `summary` 在采纳前没有别的读者**：它只被 `commit` 读一次（写进事件条目）。所以在保存那一刻改它是安全的、也是唯一的时机。

### 3.1 后端

| `app/api/routes_turn.py` | 新增 `PUT /api/sessions/{sid}/candidates/{candidate_id}`，body `{prose}`；走 `_traced_runner`（会触发 LLM，必须进 trace）；404 / 400 |

三处判据：

1. **候选必须还在**：采纳 / 放弃都会把候选文件删掉 → `load` 取不到 → 404。⚠️ **不查 `status`**——全仓没有一处会把它改成 `pending` 以外的值，查了就是一条没有牙齿的分支（`test_edit_is_gone_once_the_candidate_is_adopted` 是这条的实证）。
2. **正文非空**（`strip()` 后）：编辑框带进来的首尾空白顺手吃掉，不该进事件日志。
3. **正文没变就不发核对**：`text == (candidate.prose or "").strip()` 早退。点开编辑框又关掉是最常见的一种"保存"。

参照区（`build_qc_reference`）沿用**该候选自己存下的 `participants`**——与重掷 2026-09-23 那次修复同一条纪律：**在场 ≠ 上缴过**。老候选文件没有这个字段时退化成"场景 + 主角两条边界"，退化但不误判。

`worker="qc"` 复用 `config.AUX_WORKERS`（"谁是辅助"的唯一名单）：这是同一族的核对活，不为它新开角色名。

### 3.2 前端（`web/dist/`）

- **控件文字化**：`◀ · 1/2 · ▶ · 重抽 · 编辑 · 采纳 · 放弃`——只留 `◀ ▶` 两个图标（方向自明），其余四个动作一律文字（原来 3 个动作时 `🎲 ✓` 够用，涨到 6 个就得靠猜）。
- **手改态**：`textarea.message-edit` **替换**正文显示（`textEl.hidden`），控件行只留「保存修改 / 取消」；退出时把 `textarea` 整块**摘掉**（不靠 `hidden` 挂着一块看不见的 DOM，`display` 覆盖那类坑就无从谈起）。
- 🔴 **编辑框要和正文档一样大**（用户补正：「编辑的框太小了，要和稿件的一样大」）：高度由 `fitEditorHeight()` **跟着内容量**（进入编辑态量一次 + 每次输入重量 + 窗口 resize 重量）。三条硬约束：
  - **`padding` 必须为 0**——文字要按**同一列**折行；给了左右 padding，可用宽度就比正文窄，同一段话多折一行，高度自然对不上。
  - **不写 `line-height`**，靠 `font: inherit` 连行高一起继承（正文是 `normal`；写成 1.6 每行都更高）。
  - **必须补回边框高**：`scrollHeight` 只含 padding 不含边框，而全局是 `border-box` ⇒ 高度 = `scrollHeight + offsetHeight - clientHeight`，否则永远比正文矮 2px。
  - `min-height: 140px` 只是可用性下限（真实稿件 6 段左右远超它）；`resize: none`——高度已跟着内容走，留个拖拽角只会被下一次输入冲掉。
  - ⚠️ jsdom **不排版**（三个尺寸恒为 0）⇒ 这条行为守卫靠"给原型塞假尺寸"验（`smoke.test.mjs`），CSS 那半条退化成源码断言。
- 🔴 **宽度也要一样**（用户第二次补正：「高度是好了，但是宽度还是太窄」）。坑在 **flex 的内在宽度**：`.message.npc` 是 `align-self: flex-start` ⇒ 宽度**由内容决定**（正文是长文本，正好顶到 `max-width: 72%`）；而编辑态放的是 `textarea`，它的 `width: 100%` 落在"宽度还没定"的父级上会被当成 `auto`（循环百分比）⇒ 退回**内在宽度**（默认 `cols≈20` 字符），整块缩成一条窄条。
  - 修法：宽度提成一处 `:root{--bubble-max:72%}`，正文读 `max-width`、编辑态读 `.message.editing{width:var(--bubble-max)}`（**必须有确定的 width**，`textarea` 的百分比才有基准）。
  - `editing` 类由 `classList.toggle("editing", editing)` **一处**管两边；`clearCandidateControls()` 里还要单独摘一次——那条路径真实可达（`syncPendingFromServer` 发现候选已被采纳 ⇒ 清控件，而气泡**留在对话里**，类不摘就有一条空消息占满宽度）。
  - ⚠️ 宽度也是 jsdom 量不出来的 ⇒ 守卫拆成"类名在不在"（能真跑）+ "两处读同一个变量"（只查源码）。
- **`state.editingId` 存候选 id，不是布尔**——见下条。
- **界面不谈摘要**：保存成功只换正文，不往对话里塞提示、不显示摘要前后对比。

两条守卫（都做了变异检验）：

| 守卫 | 不做的后果 |
|---|---|
| **手改途中提交新输入 → 拦下**（提示"先点保存修改或取消"） | 提交会顺手把当前候选**静默采纳**，手改就白改了（服务端从没收到过这次修改）。拦下时**不清空输入框**——玩家敲的字不该被吞掉 |
| **编辑框按候选 id 绑定**，换了候选整块收掉 | 旧编辑框顶着 A 的正文活到 B 头上，一点「保存修改」就把 A 的正文写进 B 的候选 |

## 5. 已知代价（玩家需要知道的）

- **就地改 = 原稿没了**。改之前那一版只存在于"我脑子里/别的地方"。
- **重抽不承接手改**：点「重抽」是**从头再写一稿**（不喂上一稿、也不喂手改稿），它作为**新的候选**加进来，手改稿仍在候选列表里（用「上一稿 / 下一稿」可回去）。这一点写在「重抽」按钮的 title 里。
- **手改只改文字**，不改世界副作用（时间 / 在场 / 私密 / 地点 / 目标 / 状态）——那些仍由**采纳那一刻的审计**从正文推断。所以"改掉正文里泄漏的秘密"会同时影响摘要（本方案负责）与审计的推断（本来就会重算），两条都不需要玩家额外操作。
