## 3. A′ 档：已有一份完整方案在等触发条件 —— 文档只在「判据」上有增量

### 3.1 玩家输入的地位：那是"他想做的事"，不是"已经发生的事"

**文档依据**：§1.5「玩家能力不等于玩家意志」· §11 末「绝不让'玩家文字'直接覆盖世界状态」（原文例子：玩家说「我让守卫同意了」⇒ 系统应解释为"尝试让守卫同意"，**而不是已经成功的事实**）· §12.3「防万能主角」（成功至少付时间/金钱/资源/风险/关系损耗/机会成本/信息成本中的一种）· §25「世界不会为了让我开心而自动让路」。

**AIWorld 现状（四层，全部核对过）**：

| 层 | 现状 | 位置 |
|---|---|---|
| **二级 · 情节合理性**（规则层） | 5 条里**没有一条**讲这件事 | `workorder.py:849-866` —— 信息边界 `:851-854` · 抉择归属 `:857-861` · 设定一致·位置 `:862-863` · 连续性 `:864` · 不出戏 `:865` |

## 4. B 档：真缺口（值得做，按代价排序）

### 4.1 NPC 认知的两条空白：允许记岔 + 态度有惯性 —— 零代码 ⭐

**文档依据**：§13.2「记忆不是事实数据库」（允许**遗漏 / 误解 / 偏见 / 片面 / 错误传闻**，因此 `World Truth ≠ NPC Memory`）· §1.4「状态变化应具有惯性」（关系不能每轮重置）· §5.2-5.4（认知状态机 / 三档变化幅度 / **冲突恢复不是瞬时完成**：「不要自动'上一轮吵架，下一轮就和好'」）。

**AIWorld 现状**：

| 事实 | 位置 |
|---|---|
| `known_set_block` 是**机械计算**的（亲历 ∪ `known_by` ∪ 同区域公开），并硬写「清单外的事件这些角色一律不知道」 | `workorder.py:589-624` |
| ⇒ 知识是**两级**的：知道就全对，不知道就完全不知道。**没有中间态** | 同上 |
| 全仓搜「惯性 / 和好 / 翻脸 / 态度 / 好感 / 记错 / 误会 / 误解」在 `app/` 下**零命中**（唯一命中是无关的"以为"用法） | `grep -ri` ⇒ 无相关约束 |

⇒ 两条**都是空的**，而且是同一族：**认知的时间维度与不完美**。

**落地形态（两条提示词）**：

> **(a) 记忆是有出入的**：角色确实知道某件事时，他记住的多半是模糊版本（时间记岔、细节夸大、把两件事并成一件）。「已知集」划定的是他**知道什么**，不是他**记得多准**。

> **(b) 态度有惯性**：一个人对另一个人的判断不会一轮翻面。要变，得戏里有看得见的原因；吵完架不会下一轮自动和好。

🔴 **必须遵守二级的既有纪律：不新增条目**（沿用方案 §3.1 的判据）。落点建议：(a) **并入「信息边界」条**（同族——都是"谁有权/知道什么"）；(b) 并入「连续性」条，或放三级预设（差别是**硬一点还是软一点**）。

**为什么值得做**：信息不对称与"人不会瞬变"是"活世界"最直接的体感。现在 AIWorld 只有"知不知道"两级，加上"记岔"才是三级；而"上一轮吵完下一轮和好"是最容易让玩家出戏的一种。

**验证**：一条实测即可——同一段关系，跑一次冲突回合，看下一回合 NPC 的语气是不是"翻篇了"。

### 4.2 NPC 认知的深层：允许「他以为 X」留下来 —— 小改，要你先拍板

**文档依据**：§6.1 三层信息（`Truth → Information → Belief`，`Belief` 单独一层）· §6.3 信息壁垒（跨圈必须经具体路径传播）。

**AIWorld 现状**：容器**已经有了**，挡着的是纪律。

| 事实 | 位置 |
|---|---|
| `StateItem` = 自由文本 + 可追溯（`source_event`）+ 可见性标签（`public`）+ 可撤销 | `app/ledger/save.py:16-48` |
| 所以「他以为主角是官府的人」**今天就能写成一条状态** | 同上 |
| 真正挡着的是**审计的纪律**：「只填正文**已经写成事实**的；不写意图、**不写别人的评价**」 | `workorder.py:1128` |
| 上限：每人 `STATE_CAP_NPC = 3` · 单回合新增 `STATE_ADD_PER_CHAR = 1` | `workorder.py:80` · `:86` |

**落地形态**：给审计开一个**认知桶**（与 `state_add` 并列），允许写"某人以为 / 某人怀疑…"，闸门是"正文里找得到依据"。

⚠️ **取舍要你定**：
- **共用同一个桶**：简单，但认知会挤掉"长期事实"（每人只有 3 格），玩家得自己权衡；
- **单开一桶**：清楚，但注入多一段，且要新定一个上限。

### 4.3 场景的运行时状态 —— 小改

**文档依据**：§10.1 `LocationState`（`opening_hours` / `current_population` / `conditions` / `owner_or_faction` / `active_events`）· §10.2「地点状态本身应该是叙事素材」（商店 → 缺货 → 装修 → 临时关闭 → 换老板）。

**AIWorld 现状**：

| 事实 | 位置 |
|---|---|
| `Scene` 只有 `id / aliases / perceivable / region / image` | `app/world/models.py:42-59` |
| `perceivable` 是**作者写的静态描述**，每轮原样拼进提示词，**不会变** | `scene_snapshot_block`（`workorder.py:549-586`，第 4 行） |
| 运行态只挂在**人物**上：`save.entities: dict[str, EntityRuntime]`（`lifecycle` + `states`） | `app/ledger/save.py:51-58` |
| **场景没有对应的运行态**；场景侧唯一的"活"是候选册 `save.locations`（只记候选，走 `/file` 才成资产） | `save.py:141` · `transaction.py:338-352` |

**落地形态（尽量不新增模型）**：

- 把 `states` 这一套**平移到场景**：`save.scene_states: dict[str, list[StateItem]]`（或直接复用 `EntityRuntime`）。
- **三条链全部复用现成的**：
  - 审计提议 → 给 `state_add` 加一个"主体是场景"的维度；
  - 到期清算 → `_expire_states`（`transaction.py:530-561`）只依赖 `until`，**与主体是什么无关**，直接可用；
  - 玩家撤销/修订 → `revoke_state`（`:752`）/ `revise_state`（`:793`）同形。
- 注入侧：`scene_snapshot_block` 第 4 行后加一行「此地现状：…」（**无状态时不出现 ⇒ 零成本**）。
- 前端：**并进**已有的位置面板 / 状态面板，**别新开入口**——`docs/方案-位置面板-AIWorld.md` 已经在做"此刻"的展示，重复造会打架。

🔴 **按 AIWorld 既有判据收窄**：只收**长期事实**（"歇业""在装修""被封了""换了老板"）。
**不收「此刻有几个人」**，三条理由：① 那是 `present_at` / `where_is` 的活（由事件流推导），已有；② 它每轮变，属"一次性的当下"，正是"只收长期事实"明令不收的三类之一（`workorder.py:1125-1127`）；③ 会与 4.4 的补账互相污染。

### 4.4 跳时补账：玩家离开后的世界 —— 中改，价值最高、风险也最高

**文档依据**：§7.3「离开后的世界」· §19.2「玩家长时间离开」数据流（Time Advance → Scheduled Events → NPC Life Simulation → Regional Changes → Memory Update）· §8.3「事件必须留下后果」· §25「我离开几天再回来，这个地方可能已经变了」。

**AIWorld 现状（结构性缺口）**：

| 事实 | 位置 |
|---|---|
| 时钟**只在一处**推进：采纳那一刻 | `transaction.py:263` |
| 全仓没有回合外推进：搜 `create_task` / `BackgroundTasks` / `while True` / `asyncio.sleep`，只命中 SSE 生成器与 LLM 重试退避 | `app/api/routes_turn.py:119-120` · `app/core/llm.py:210` |
| "离开三天"今天的效果 = 时钟从 T 跳到 T+3d（`clock_to` 优先于 delta），**事件流里这三天是空的** | `transaction.py:248-254` |
| 有一半**已经有的**：`_expire_states` 会按新时钟清算到期状态（"病三天"会好） | `transaction.py:590` → `:530-561` |

⇒ 缺的不是"到期"，是**"世界在动"**。

**落地形态（AIWorld 版：不引入后台）**：

- **触发点**：`Transaction.commit` 已经同时知道 `clock_before`（`:234`）与 `clock`（`:264`），跨度 ≥ 阈值（建议 6 小时）时，**在同一次调用里**多跑一段轻量补账。不开线程、不开定时器。
- **谁做**：**审计**。它本来就只在这一刻跑（`:191`），且已有"世界侧"输出桶（`npc_moves` / `lifecycle`）。**不新增 agent、不新增模型出口。**
- **产出形状已有现成的**：`transaction.py:367-387` 的 `npc_moves` 留痕事件就是「`body` 空 + `summary` 一句话 + `known_by` 机械算」——补账事件就长这样。
- 🔴 **四条闸门，缺一不可**（对象是本地 7B；不加闸门必胡编，而补出来的会变成**不可逆**的既成事实）：
  1. 只准用**已注册的人物 / 场景 / 已有目标**，不准发明新名字、新组织、新事件线；
  2. 只准写**位置移动 + 状态增减**，不准写情节（不对白、不定冲突结果）；
  3. 条数上限（建议 3 条）；
  4. **默认关闭**——按既有先例做成 `Settings` 开关（`audit_enabled` / `qc_enabled`，`app/config.py:118-119`），走 env + `PUT /api/settings`。
- ⚠️ 第 4 条不是保守：**事件流是史实层、不可变**——`Transaction` 只有 `discard_turn`（未采纳的候选），**已提交的事件没有回退路径**。先自己开着看两轮，再决定要不要常开。
- 与文档的差别：文档要"周期调度"（§14），AIWorld 做的是**跳时一次性补账**——同样的体验目标（回来一看变了），代价差一个数量级。
