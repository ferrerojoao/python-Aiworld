## 0. 一页纸

| | |
|---|---|

### 0.1 ✅ 已定决策（2026-09-23，按推荐设置落定）

| # | 决策 | 理由（一句话） |
|---|---|---|
| 1 | **端点 = 独立 `GET /sessions/{sid}/locations`**，不塞 `/state` | `/state` 是**每回合都拉**的，位置却是**全量**视图；独立端点才能做到"没打开抽屉就不发请求"（沿用转正页 `/draft` 的既有纪律） |
| 2 | **「依据」折叠第一版就做** | 数据现成（`where_is` 返回的就是事件 dict）；判据同转正页「证据」——**"可变的字段必须在清单里看得见它是从哪来的"**。不做的话没人知道"3 天前"是怎么来的 |
| 3 | **不加左栏入口** | `MEMORY-DETAIL` §17B 已定"不放左栏"（左栏已挤）；且**左栏「在场」的语义是"此刻这一幕"**，而位置面板是"**全量**"⇒ 放进左栏会混掉两套语义。M14 的教训是"**别只放导演窗口**"，抽屉 tab 已满足 |

| 5 | **「场景疑似改名」警告独立成小活**，不绑在面板上 | 面板是大活、警告是小活；绑一起会让小活等大活。规格见 `docs/方案-地图-AIWorld.md` §12 |

## 1. 与三件邻事的关系（🔴 先读，防重复造）

四件事**共享同一批数据**（`scenes.json` + `where_is` / `present_at` / `region`），且互相替代：

| 功能 | 回答的问题 | 状态 |
|---|---|---|
| 左栏「在场」/ **顶栏场景卡** | **此刻这一幕**里在哪、谁在 | ✅ 已实现（附图待加） |
| **位置面板**（本文） | **全量**分布：谁在哪、某地有谁、多久没露面 | ⬅️ 本文 |
| 刷新位置（`MEMORY-DETAIL` §18/§19） | 把**陈旧**的位置变新 | 未做（影响面已评估） |
| 地图 = **一张画** | 这一带**长什么样** | 未做（可复用附图那套） |

🔴 **两条红线**：

1. **"此刻"已经有人做了** —— 顶栏场景卡**就是**"此刻这一幕：哪里 + 谁在"。**位置面板不要做成第二个"此刻"**，它是**全量**（含**玩家不在**的场景）。这也正是它存在的理由：左栏 / 场景卡只表达当前这一幕，玩家看不见"刘德福现在在哪"。
2. **甲（分区地图）是位置面板的延伸，不是替代** —— 所以**别并行做两遍**。

## 2. 🔑 「最后目击」机制**已经存在**（回答"是不是已经有"）

**是的，而且比"有机制"更强 —— 它已经在用了**：

| 环节 | 位置 | 说明 |
|---|---|---|
| **相对时间工具** | `_rel_seen(clock, at)`，`app/core/workorder.py:523` | docstring 原文：「快照新鲜度：**最后目击时刻**相对当前时钟的人类表述；任一侧解析失败返回空」→ `刚刚`（<10 分）/ `N 分钟前`（<60）/ `N 小时前`（<1440）/ `N 天前` |
| **唯一调用点** | `scene_snapshot_block`，`workorder.py:549`（调用在 `:576`） | **提示词**里 —— **前端拿不到** |
| 位置索引 | `last_location[pid] = event`，`queries.py:97` | 仅 `kind == "narrative"` 且 `location` 非空时更新，对该事件的每个 `participants` 逐个记 |
| 查询 | `where_is(name)` → `_probe`，`queries.py:208` | 直接取 `last_location.get(entity)`，返回**事件 dict**（带 `at`） |

**编剧现在收到的就是这段**（`scene_snapshot_block` 的输出，原文）：

```
当前时间：<clock>
在场（括号内 = 该角色最后被记录在此的时刻，久未见面的要考虑他是否还在）：
    朱明（最后目击：3 天前）、王蓉（最后目击：刚刚）…
当前场景：<scene.id>
<scene.perceivable>
```

⇒ **三个结论**：

1. 🔑 **本面板要做的事，本质是把一条"已经喂给编剧的信息"也给玩家看** —— **零新算法、零新索引**。
2. ⚠️ **文案必须沿用「最后目击」** —— 提示词里已经这么叫了，界面另起一个名字就是又一处"**同一件事两套叫法**"（本项目对这类词有明确纪律）。
3. 🔑 **本方案的真正价值**：提示词里那句「**久未见面的要考虑他是否还在**」说明**编剧已经在权衡陈旧**，而**玩家却看不到依据** —— 面板把这份依据交回给玩家。

## 3. 视图函数：`location_view()`（引擎侧生成）

**落点与判据**：照 `state_view` 的先例 ——

- `state_view` 定义在 `app/core/workorder.py:195`（**不是独立模块**），由 `GET /sessions/{sid}/state` 在 `routes_sessions.py:726` 组装进响应。
- 那段代码的注释写死了这条纪律：**「由引擎侧生成（复用提示词那套 cap 与截断），所以面板上……与提示词字面同源——前端不要自己算」**。
- ⇒ `location_view()` **放 `workorder.py`**：与 `scene_snapshot_block`（`_rel_seen` 的调用方）**同文件、能直接共用** `_rel_seen` 与 `player_display_name`。

**返回结构（建议）**：

```jsonc
{
  "groups": [                       // 第一步 = 场景平铺；第二步 = 按 region 折叠
    { "region": "上层", "scenes": [
        { "scene": "酒楼", "people": [
            { "name": "朱明", "role": "npc", "seen": "3 天前", "at": "2026-07-11T20:00:00",
              "evidence": { "event_id": "e12", "summary": "你在酒楼见到他" } } ] } ] } ],
  "special": {                      // 四个特殊组，独立成组
    "unknown":  [ "…" ],            // 位置未知
    "retired":  [ { "name": "…", "seen": "…", "at": "…" } ],   // 已退场（附"最后在 X"）
    "adhoc":    [ { "scene": "老巷旧楼", "people": [ … ] } ],   // 临时地点
    "player":   { "name": "…", "scene": "…", "seen": "…" }      // 主角，单列并标记
  }
}
```

**为什么 `special` 要独立**：见 §4 —— 它们**不是"区域"的一种**，塞进正常分组就是界面在撒谎。

**「依据」折叠（✅ 已定：第一版就做）**：位置行可展开显示**那条定位事件的摘要 + 时间**（"第 12 天，你在酒楼见到他"）。手法与转正页的「证据」折叠完全相同，判据也一样：**"可变的字段必须在清单里看得见它是从哪来的"**。数据已经拿得到（`where_is` 返回的就是事件 dict）。

## 4. 分组的完整分类（🔴 六组，别只做两组）

| 组 | 判据 | 性质 |
|---|---|---|
| **有分区** | 已注册 且 `region != ""` | 正常（第二步的折叠层级） |
| **未分区** | **已注册** 且 `region == ""` | **正常** —— `region` 空 = **不传播**（2026-09-24 反转；旧口径"全域公共"已作废），是**合法值**，不是缺省错误 |
| **临时地点** | `location` **不在 `scenes.json`** 里（未注册，`_event_region` 打 `ADHOC_REGION`） | ⚠️ **不是"未分区"的子集** —— 它压根不是注册场景。**必须单列** |
| **位置未知** | `where_is` 返回 `None`（从未参与任何带 `location` 的事件） | ⚠️ **开局常态**：除主角外**全员如此**（世界还没写过任何带位置的流水）。**正常起步态，不是 bug**，界面要说明 |
| **已退场** | `lifecycle == "retired"` | `present_at` 会跳过它，但 `where_is` **仍返回最后位置** ⇒ **既不进场景组、也不该凭空消失**：附"最后在 X" |
| **主角** | `is_player` | **单列并标记**，否则会与 NPC 混在一起（他是玩家自己） |

🔴 **三条口径细节（都有先例，别自己发明）**：

1. **不含未落卡者**（用户 2026-09-19 拍板：只要"真正有卡的"）⇒ 域收到 `world.npcs`，**去掉 `save.unfiled`**。
   - ⚠️ **陷阱**：`present_at` 的域**是** `world.npcs ∪ save.unfiled` ⇒ **不能直接拿 `present_at` 的输出**，要自己按 `world.npcs` 过滤。
   - ⚠️ **代价必须写进界面**：左栏「在场」与转正页**含**未落卡者，本面板**不含** ⇒ **两处人数会不一致**，这是**有意的口径**（面板回答的是"**有档案的人**在哪"），不写明以后会被当 bug 修。
2. **临时地点顺手给"注册为场景"入口**（复用 `POST .../locations/{name}/file`，即场景转正那条路）。
3. **主角也算"有卡"**（`is_player`），照常列出并标记。

## 5. 端点：独立 `GET /sessions/{sid}/locations`（✅ 已定）

| 方案 | 取舍 |
|---|---|
| A · 塞进 `/state` | 有先例（`state_view` 就在里面）。但 `/state` 是**每回合都被前端拉**的（`refreshState()`），而位置是**全量**视图（可能几十个场景 × 人物）⇒ 每次回合都白传一遍 |
| **B · 独立端点** ✅ **已定** | 只有**打开抽屉**才拉。`/state` 的字段数已经不少（`routes_sessions.py:711-745` 一段十几项），别再长 |

**已定 B**，理由 = **按需拉取**，与转正页 `/draft` 的纪律同源（"**没展开就一个请求都不发**"）。

## 7. 第二步：分区地图（甲）＝ 本面板 + 一层 `region` 分组

**已选甲。增量只有一层**：把 §3 的 `groups` 从"场景平铺"改成"按 `region` 折叠"。**没有新数据、没有新索引、没有新算法。**

⚠️ **必须写进界面的两条限制**：

1. **玩家新建的场景 `region` 恒为空** —— 「转正」表单**不收 `region`**（2026-09-19 决定：守最小需求，场景「听域」输入不加）⇒ 他们**全落进「未分区」组**。
2. **有的内容包全空** —— 实测 `content/*/scenes.json`：`sgjz` = 集市 / 下层 / 暗渠 / 上层（**天然分层，效果最好**）· `shenshan` = 深山村 / 北安县城 · `anmei` = 秋叶原 · **`qingshi2` / `wuxia` 全空** ⇒ 这些包的地图**退化成平铺清单**（仍可用，只是没有层级）。
