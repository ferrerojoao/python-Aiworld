## 〇、数据契约：NPC 档案 / 事件条目 / 世界设定 / 元配置

> 本章是数据底座，是所有机制共同引用的内容来源：NPC 档案（①②③ 三分类）、**角色状态**（长期事实，与此并列的第四类，见后）、事件条目默认公开与 known_by 私密名单、秘密的存放规则（幕后注 / 注入记忆）、世界设定两级（概要常驻 / 世界书按需）、元配置·叙述预设。

### ① 人物卡 · 初始状态　（作者离线预制 · 开局写死 · 只读）

- **内容 = 外貌 / 人格**。人格合一格：性格 + 特点 + 说话风格 + 前史 + **身份定位**（职业/辈分/社会身份等定位资料并入此格，2026-09-05 拍板：不设独立身份字段）——全部为 LLM 语义消费内容，供台词书写与文风核对时整体取用（性格/特点回答"他是怎样的人"；说话风格 = 语气/用词/口癖；**前史 = 游戏开始前已存在的过去**，童年/来历/前缘/旧伤，作者开局可写；补充童年经历类资料一律落此格，② 是运行时事件流的累积，开局前的事属于 ①）。UI 层可在格内分段展示（性格 / 前史），存储保持一格。**主角就是人物表里的一员（2026-09-13 用户拍板）**：主角与 NPC 完全同构（同名/外貌/人格 + 幕后注/自知隐秘），存在世界包的 `npcs/` 里，由 `is_player` 标记认出、有且仅有一张、**不可删除也不可退场**；差别只有一条——主角永远不配 Actor（他的抉择只能由玩家给）。**"谁是主角"只在开局前可改（2026-09-21 用户拍板）**：账本一落第一条正文（`source != "opening"`）就冻结——`is_player` 不可改勾、主角不可改名（改名 = 换人物表键，与换人同类）；要换主角只能先「重置世界」。因为事件日志、位置小抄、角色状态、记忆切片全按**人名**索引，而目标归属的空串哨兵与质检参照区都指向"当前主角"——中途换人会静默改写历史归属、整体替换泄漏基线。背景字段已删（详情并入人格）。两字段语义：
- **自知隐秘**（玩家个人秘密）：只有玩家自己知道（如"夜里是假面骑士"）——任何 NPC 说出或提及即泄漏（同学不会说"你就是假面骑士"）；玩家可选择何时亮牌，亮牌 = 一场揭露新戏。
- **幕后注**（特殊背景）：连玩家也不知道的底牌（如"受神之加护，但赐予者名雅典娜"）——只有编剧运行时可读，用于埋伏笔/让神迹自然发生，正文揭示即泄漏。
- **秘密 = 未叙述真相**（规则见本节「秘密 · 叙述即公开」），作者下笔时按知情面分两格：
  - **幕后注**（作者底牌）：**无人知道**的真相（含 NPC 自己也不自知的命运底牌与涉密前史）——可选私区，仅编剧运行时可读，永不进任何切片（含 NPC 本人）与玩家视角。
  - **personal_secrets**（NPC 自知隐秘）：该 NPC **自己知道**、不为外人道的心结 / 往事 / 把柄（"他爸欠了赌债，他最不愿提"）——进该 NPC 本人的 Actor 深抉择切片（"你心里的事"），**不**进玩家、其他 NPC 与任何引用域；编剧全知侧同见（标注"XX 自知"）。真相首次被叙述（玩家撞破 / 查出 / 他人泄露）时落库为新事件，此后按叙述情境入引用域。
- **只读 + 增补路径**：① 的内容在开局后保持固定，② 经历（追加）与 ③ 属性（覆盖）随剧情演化；需要增厚 ① 时走**补卡事务**，两条入口**都不在导演窗口**（2026-09-13 改判）：**即兴角色转正**见三章「即兴角色三机制」（引擎获键 → 左栏「待落卡」入口 → 玩家核对落卡）；**已有卡增厚**直接在世界工作台的人物编辑表单改。起草由**模型从已采纳正文里总结**（2026-09-19 收窄旧口径——旧文写的是"只机械提取、拟稿由玩家完成"）——防线随之换成三条：① 输入**只有该主体自己的原文事件**（不喂世界书、不喂别人的卡、不喂底牌）② 提示词硬性"不许超出正文，写不出就留空" ③ **草稿带「AI 草稿」标记、与原文证据并排，玩家核对后点确定才落盘**。**不可推导的字段仍由人写**：幕后注 / 自知的隐秘定义上就是"无人知道的真相"，正文没写 → 不进落卡表单。字段增补一律经此路径完成。
- **引擎配置字段同落此卡**：
  - **has_actor 档位初值**：作者在内容包预标重要 NPC，即兴角色转正时决定初值。档位判定读世界人物表里的人物卡；玩家要调整时直接在世界工作台编辑人物卡（不经导演窗口；2026-09-05：原"正常日程"字段已移除——NPC 习惯画像不再做引擎级基线，位置推断只用"最后事实 + 身份隐含大框"）。

### ② 经历 · 随回合累积　（追加日志 · 时间线可回溯）

- **内容 = 事迹与记忆（规则化拼接条目，规则见三章）+ 当前状态缓存**（最近结算摘要：此刻位置 / 受伤 / 临时覆写），供装配、面板直取。**注意分层**：这层是**可重建的缓存**（丢了能由事件流推回来）；长期状态（免疫普通武器 / 独臂 / 病倒）是**持久事实**，另有存储，见「角色状态 · 长期事实」。
- **位置真相在事件条目**：每个事件条目自带位置与时间戳。"此刻在哪" = 该实体最近一条相关事件（记 位置 · 时间 · 来源=目击/事件/覆写）。位置由事件推导，旧事件随世界钟过期后降级为推断素材（M18 同规则）。情绪 = 引擎从该实体最近事件流得出的推断值，随事件刷新、按需现算。
- **账本状态字段同落此层**：M16 注入登记留痕（纪律见二章 M16）。

### ③ 抽象属性 · 可变数值　（内容包声明 · 引擎每回合结算覆盖）

> **暂缓**：本分类与 M5 关系结算为二期设计，v1 不在引擎中结算； schema 可预留，但 v1 不写入、不读取关系轴。

- 内容包按题材声明轴：`{id / 标签 / 范围 / 初值 / 可见性 / 归属实体}`——冒险世界 = 力量、敏捷；恋爱世界 = 好感、信任。挂玩家或 NPC。
- **关系轴**（可选标记，带目标实体，如"好感 玩家→朱明"）：标"记因"的关系轴每次数值变化自动在 ② 落一条账（谁 · 因何 · 影响谁 · ±多少），关系变化的因果全程可回溯。
- **可见性**：玩家面板只显示 `visible=true` 的轴；`visible=false` 的轴在玩家面板之外照常参与引擎结算。

### NPC 生命周期　（实体级状态位：active / retired）

- **退场 = 状态变化，实体数据全保留**：死亡 / 永久离开的终态事件由世界审计例行扫描发现 → 置 `retired`。复活 / 诈尸 = 剧情事件翻转状态，数据层随事件翻转、导演排戏。
- **retired 后的处理**：

| 项 | 处理 | 归属 |
|---|---|---|
| 主动调度与推断 | 该角色停止参与引擎的主动调度与位置推断 | 规则 |
| 数据保留 | 人物卡（含幕后注）/ 经历 / 关系轴 / 记忆条目一律保留在账本 | 自动 |
| 位置 | 死亡后最近相关事件即终点 | 规则直落 |
| 剧情目标（M14） | 未完成目标保留在账本；是否继续推进由玩家定夺（废弃=导演窗口 status: abandoned） | 玩家 |
| has_actor | 档位保留；无戏份时深抉择零触发、Actor 零调用 | 自动 |
| 关系轴 | 冻结，停止结算 | 规则 |
| 未叙述真相的揭晓 | 死者幕后注 / 注入记忆维持原样；是否揭晓（遗言 / 遗物 / 他人目击）由导演编排为戏，叙述即落新事件 | 导演编排 |

- **推论**：退场者的条目照常被他人引用、回忆——事件流作为真相层，记忆条目的可引用性与本人状态无关。
- **升格 = 角色重要性上升时 has_actor 档位单向升档**（信号与判定规则见三章「升格通道」）；升格 = 在世界工作台把该人物卡的 `has_actor` 勾上（厚度不足时先补卡，①）。建档转正（即兴 → 有卡）与派活升格（代笔 → Actor）是两条单向升档的通道。

### 角色状态 · 长期事实　（实体级：叙事事实 / 引擎开关两类）

**问题**：人物随剧情改变——杀了龙、沐浴龙血，此后"普通武器伤不了他"。这类"他此刻是什么"三类既有数据都装不下：① 是开局写死的作者设定；② 的事件日志**只有最近 10 条进编剧视野**（更早压成 60 字摘要，第 500 轮早滚没了）；③ 是数值轴，装不了"免疫"这种非数值事实。

- **两类，判据 = 引擎会不会读它**（**不合并成一个列表**——合并等于把确定性问题交给 LLM 去猜"这条要不要影响引擎行为"）：
  - **引擎开关类（硬）**：引擎规则自己要读的状态位。现存一个 `retired`（见上节「NPC 生命周期」）——`present_at` 跳过它，连带改变在场名单、Actor 上缴名单、世界书归属条目注入。将来如"被囚""失能"同属此类，**各自独立成字段**。
  - **叙事事实类（软）**：免疫普通武器 / 独臂 / 病倒 / 身份门派 —— 引擎一行都不读，唯一职能是**让编剧与审计知道**。落 `states[]` 条目。
- **存储与生命周期**：存在**存档**（`entities[人名].states[]`），**与存档同生命周期**——重置世界即清零（这个世界重玩一遍，龙血也该重新喝）。世界资产里的人物卡维持"开局固定 + 补卡事务增厚"的原语义不变。
- **条目字段**：`text`（一行事实，直接进提示词）· `since`（获得时的世界钟）· `source_event`（哪条正文给的——**可追溯、可撤销的锚点，也是成因的出处**）· `public`（**这条状态**旁人看不看得见）· `until`（可选，到期失效："病倒三天"不是永久事实）。
- **状态只写现状，不写成因**（2026-09-15 拍板）：一条状态 + 一个 `public` 布尔**表达不了"成因私密、表现公开"两层**——写成"沐浴龙血，普通刀剑伤不了他"，标 `public=true` 会把成因一起交出去，标 `false` 又连表现一起藏起来，两头都不对。**解法不是拆成两条**（吃两个额度、撤销要撤两次、关联是隐式的），而是让状态只承载**表现**："普通刀剑伤不了他"进 `text`，成因（"沐浴过龙血"）留在产生它的那条事件里、由 `source_event` 指得着。于是 `public` 的含义收窄成干净的一句：**这条状态旁人看不看得见**——看得见（`true`）就写成旁人能观察到的表现（"左腿瘸了"）；看不见（`false`，默认）就写成不外露的事实（"其实色盲"）。**这是提示词纪律，不是机械守卫**：成因与表现的分界中文判不成硬闸，靠**三处工单的口径统一**（`state_lines` 只写现状 + 编剧侧「秘」标记 + Actor 侧两桶分法）+ 玩家撤销兜底。
- **可逆性**：叙事事实多数可逆或带期限（病倒 / 骨裂 / 中毒），**退场不可逆**——这是两类状态不同类的又一处证据。撤销按 `source_event` 逐条追溯删除。
- **注入三处，口径不同**：

| 消费方 | 注入内容 | 口径 |
|---|---|---|
| 编剧 | 全部 `states` + 不公开条目的「**秘**」标记 | 全知。主角段恒在（他永远是「玩家资料」那一段）；NPC 在场才注入。**成因不在状态里**——要从事件日志 / `source_event` 看。「秘」是给编剧用来填 `actor_questions[].context` 的：他是唯一决定"谁该知道什么"的人（2026-09-15） |
| 世界审计 | 全部（不带标记） | 全知。否则会判出与状态自相矛盾的正文（"他被一剑穿心"）。审计不写 NPC 情境，标记对它没用 |
| NPC Actor | **自己的全量 + 在场旁人的 `public` 条目** | 自己的**不过滤 `public`**——`public` 是"旁人看不看得见"，对本人没有意义（他当然知道自己腿断了；不给就会出现"腿伤在身却健步如飞"）。旁人的只给 `public=true`（这才是这个字段唯一的正经用途），不在场一律不给。两桶都不带 `（至 …）` / `（秘）`——那是给编剧排布用的（2026-09-15 接） |

- **产生三条路**：

| 路径 | 触发 | 提出者 | 确认 |
|---|---|---|---|
| 审计提议（主路） | 正文写出"龙血浸透全身" | 世界审计 | 采纳动作本身即确认 |
| 导演声明（**已落地**） | 玩家 OOC 说"我现在应该免疫刀剑了" / "把朱明那条腿伤撤了" / "那条写错了，是右腿" | 导演 | 既有两步确认门（同 retire / inject_memory）：`state_add` / `state_revoke` / `state_revise` |
| 作者预置（未做） | 世界工作台手填 | 作者 | 直接落（开局就存在的状态） |

- **审计纪律（防幻觉）**：审计只能"从正文里**读到**"已发生的变化，不发明；采纳时正文查无实据的提议**直接丢弃**。每次落地**必须同时落一条史实事件**——`source_event` 据此指得着，"谁由这件事知道"复用既有 `known_by` 与听域推算，不另造机制。
- **门槛：什么才算状态**（2026-09-14 收紧）——**只收长期事实**：这个角色**此刻是什么**（体质 / 伤残 / 长期病症 / 能力 / 身份处境）。自检问句：*过几天、几十轮回头看，这条还成立吗？* 这场戏结束就没了 → 不收。**不收的三类**：① 消息 / 情报 / 听说的别人的事（"听说她妈住院了"）——那是**事件**（② 已承载），要长期追踪走 **M14 剧情目标**，不要塞进状态；② 一次性的当下（心情不好 / 手上沾了泥 / 拿着棍子）——随时会变；③ 该角色自己的隐秘与前史（"他爸欠了债"）——那是 ① 人物卡的事。**拿不准 → 不收**：状态常驻后面每一轮的提示词，宁缺勿滥。能说清终点的给期限（"病倒三天"），到点**失效**（编剧不再读到）——**但不删条目**（2026-09-14 晚改，见下条）。**门是提示词纪律而非机械守卫**——中文语义判据做不成硬闸（"额角缠着纱布（前几天打架留的）"含事件信息却确实是状态），硬拦必然误伤；玩家撤销是最后一道闸。
- **与 ② 的边界（重要）**：状态由事件产生（史实是真相层），但**独立保存、不随事件窗口过期**。② 里说的"当前状态缓存（位置 / 受伤）"是**可重建的缓存**——丢了能由事件流推回来；状态是**持久事实**，丢了等于永久失忆。这就是它不能只挂在事件日志上的理由。
- **与 ① 的边界**：① 是作者预制、开局固定；状态是玩出来的、随回合累积。要给某 NPC 补一条**开局就存在**的先天状态（"天生盲眼"），走 ① 的补卡事务或世界工作台。
- **与 ③ 的边界**：③ 是可结算、可比较的数值（好感 42）；状态是非数值的定性事实。同一件事若既要定性又要数值（"中毒" 与 "中毒程度 30/100"），两者并存、互不代替。
- **一期落地范围**：只做**叙事事实类**（`states[]` + 三处注入 + 审计提议）。引擎开关类不新增（`retired` 维持现状）；"复活"仍属未落地设计。
- **玩家如何知道、如何撤销**（2026-09-14 拍板）：**知道**分两处，按"时效 vs 查询"分——① 左侧栏「**本回合变化**」分区：只列最近一次采纳带来的增删（新增的给 `×` 就地撤销，已结束 / 已到期 / 已撤销的灰字标注），无变化则整块不出现；② 顶栏「**状态 N**」徽章 → 抽屉「状态」页：**当前全量**，按主角 / 在场 / 不在场 / 已退场分组，含不在场者（便于查"朱明身上还有没有旧伤"）。**灰显只有一种含义 = 编剧这一轮读不到这条**（超出注入上限 / 不在场 / 已退场 / 已到期），与提示词同源——面板上"编剧能看到哪几条"由引擎自己算，玩家因此能理解"我明明沐浴了龙血，编剧怎么不记得"。**撤销**：删条目 + 一条"玩家撤销"的记账事件（**正文与已有事件不动**——史实不可变，改的是"编剧此后认为他是什么"这个运行态），逐条、**永久可撤**（面板里每一条都给 `×`，含不在场 / 已退场 / 已到期的——面板是唯一入口，不给就等于"这条永远清不掉"），撤销后那一行原地变灰而不是消失。**刻意不做"已撤销清单"注入审计工单**：正文里那场戏还在，审计再读到就再提议一次，玩家可以再撤一次——不为此在每份工单里常驻一行（2026-09-14 拍板）。
- **到期 = 失效，不删条目**（2026-09-14 晚改）：`until` 是**审计单方面**给的，玩家没有异议渠道；到点直接删条目就等于让"审计写了个期限"变成一条事后既查不到、也撤不掉的操作。所以到期只**标记失效**（编剧与审计从此读不到，正文不再受它约束）+ 落一条"状态结束"史实，条目留在存档里、面板上灰显「已到期」并**保留撤销入口**——玩家随时能清掉。
- **玩家可以主动加 / 撤 / 改**（2026-09-14 晚加，2026-09-16 补"改"）：原本链路是单向的"审计提出 → 玩家撤销"，审计漏报时玩家手上一件补救工具都没有。现在**导演窗口**（OOC）能增能撤能改：`state_add` / `state_revoke` / `state_revise`，走既有两步确认门（与覆写 / 记忆注入 / 改判 / 剧情目标 / 退场同级——导演窗口的定义就是"改账本"）。**手动加不做语义门槛**（守卫只管格式与归属）：审计那套"只收长期事实"是防它自己在正文里过度发挥的；玩家已经拍板的事再拿语义闸拦人很荒谬。手动改动同样进「本回合变化」留痕（刚动完就能一键反悔）。
- **`state_revise` = 原地改，不换条目**（2026-09-16）：改的是字段（文字 / 期限 / 可见性），`id` / 起始时间 / 成因指向**全都保留**——"他什么时候起就是这样的"不会因为改一个错别字被重置成现在。"撤销 + 新增"也能换文字，但正是会丢掉这三个锚。只认 `state_id`（导演工单里的清单逐条带 id，照抄即可），**不给 `{npc_id, text}` 退路**——那个退路在"改"里天然歧义（text 是"要改的那条"还是"改成什么"），猜错就是改错一条事实。**不给的字段不动**（所以 `until` 给空串＝清掉期限）；值与现值全同 → 不落事件。已到期的条目改不了（要它回来请撤销后重加）。左侧栏那一行显示成「旧 → 新」，改错了仍可撤销。

- **不公开的唯一标签是「秘」**（`public=false`，2026-09-16 拍板）：**四处同词**——编剧工单的状态行、导演窗口的状态清单、抽屉状态面板、左侧栏「本回合变化」（新增 / 修订 / 已结束各行，只要那条状态不公开就挂）。语义就是把 `public` 透给玩家："这条 NPC 看不出来"，省得疑惑 NPC 为什么没反应。早先"外人看不出"（面板）与"旁人看不出"（`state_revise` 的记账文案）两种说法**已废弃**——同一个概念换一种说法，玩家得重新猜这两个是不是一回事，导演也要再对照一次（记账文案现为 `可见性「公开」→「秘」`）。**左栏挂得上，前提是留痕带字段**：`last_state_change` 的五个桶（`added` / `removed` / `expired` / `revoked` / `revised`）每条都带 `public`——左栏读的就是这份数据，而"已结束 / 已撤销 / 已到期"的那几条在 `state_view` 里已经查不到。老存档没这个字段时不挂（宁可不标，不要误标）。

### 秘密 · 叙述即公开（事件条目默认公开 · known_by 私密名单）

**结算范围 = 玩家可感知**：结算只发生在玩家在场的戏与玩家声明跳时后的简报（M20 / M8 时段戏）。因此**每条叙述性事件落库时玩家都在场或已见报**——事件流里没有"玩家不知道"的情节条目。不被叙述成戏的真相不进事件流；导演的静默调度（M18 覆写）落统一事件，只描述位置、不承载情节，玩家在戏中见证其效果。

- **公开 = 默认态**：叙述性事件落库**默认不挂 known_by**，即为**公开条目**——玩家与任何 NPC 皆可引用，地位等同公共知识（校门口打架传遍全镇由此而来）。公开 ≠ 必被提及：引用与否由叙述层相关性决定（说书人选材 / 导演排戏 / 质检拦突兀）。
- **`known_by`（私密名单 · 可选字段）**：事件被判定为私密时才写，值 = **知情者闭集**——当场在场者集合（M18 查询：最近位置 = 该场景的实体；注入记忆条目 = 被注入者，见 M16；导演静默覆写是位置记录、不载知情语义）。职能 = **记忆切片边界**——NPC 只引用公开条目与 `known_by` 含自己的私密条目，名单外的 NPC 查不到这条。玩家见证每条叙述性事件：公开条目人人可引，私密条目以在场者身份落在 known_by 内。事件正文是已发生史实、落库原样保留；known_by 是访问控制状态，可按本节「访问状态改判」变更——正文与访问权分层。
- **挂载判定 = 正文内容（2026-09-09 从情境公式改版）**：落库时审计按正文内容判这场戏**有没有被场外自然得知的通道**——判据是"外人会不会知道这事发生过"，不单看地点：私下交底、咬耳朵只让对方听见、无人看见的交易、隐蔽处行事 → 私密（挂当场在场者闭集）；当众冲突、大庭广众下的对话、旁人可见可闻的活动 → 公开（条目公开，风闻再过听域筛）。导演排戏时判定、落库即定初值，不为"要不要保密"增设任何字段或场景属性；初值判错可经玩家纠错改判（见下「访问状态改判」）。
- **访问状态改判（正文史实不可变 · 访问权可修正）**：known_by 是**访问控制状态**而非一次写死的记录——正文（当时发生了什么）一经落库永不修改；"谁能引用"这一访问状态允许**修正**。改判只重设访问状态：不产正文事件、不改任何旧条目正文，玩家在导演窗口提出、导演执行后落账。改判粒度 = **单条事件**，逐条点名、逐条执行。
  - **改判私密 · 玩家纠错（公开 → 私密）**：玩家回看事件日志，认为某事件当时实为私下情境（密室对话 / 四下无人）却被落成公开 → 要求导演改判 → 重设 known_by，**名单由导演/玩家直接给定落账**，引擎不做检索起草。改判是**补救行为**：事件公开期间可能在剧情上传给了在场者之外的任何人乃至无数人，逻辑上不可能全部收回；玩家选择改判，即**接受"已传开者收不回"的逻辑代价**（为更大的叙事理由压过它）——名单内 NPC 保留知情，名单外 NPC 自此查不到这条，已传出的部分不做追溯、不设传开闸。
  - **改判公开 · 玩家纠错（私密 → 公开）**：玩家认为某私密条目系导演误挂名单（实为公开可闻情境）→ 导演清空名单恢复公开。
- **世界事实公开化（官宣 / 恋情公开）不靠改判，靠叙述**：两人决定公开关系 → 导演排一场公开戏落新事件（当众宣布 / 牵手同游，公开情境）→ 全镇自此可引"他们在一起"。**历史私密条目保持私密**——官宣开的是"关系状态"这条新事实的引用权，不是翻旧账；当年私密约会细节仍只有当事人在场者可知（真实世界同理：官宣后别人知道你们在一起，仍不知道你们约会时的私密细节）。玩家想让某条具体历史私密条目一并公开，逐条点名走上方「改判公开 · 玩家纠错」。
- **秘密 = 未叙述的真相**：事件流对玩家无盲区，"秘密"因而不是事件流上的隐藏条目，而是**尚未被叙述成戏的事实**，三种形态：① 幕后注（作者底牌 / 涉密前史，见 ①）；② NPC 档案注入记忆（导演后台补料，见 M16）；③ 导演排戏意图。三者都进不了玩家视角与任何 NPC 切片，导演运行时可读。
- **揭晓 = 叙述一场戏**：玩家撞破 / 查出 / 他人告发 / NPC 主动坦白 → 导演排一场戏 → 真相首次成为正文 → 落一条**新事件**，按叙述情境入引用域（私下坦白 = 私密条目，known_by = 当场在场者；当众揭发 = 公开条目）。旧条目原样——**知情扩散只经新戏落账**，正文事实不回头改写；已成文条目的访问修正（改判私密 / 改判公开）与关系公开化（官宣）走上方「访问状态改判」「世界事实公开化」两条通道，与正文改写两回事。被转告的 NPC 其知识来自转述 / 共历的新戏条目。
- **知情差异照常模拟**：已叙述的**私密条目**其知情差集 = known_by 查询；公开条目无差集（人人可引）。玩家"看见却装不知"→ 对方按不知演，亮牌 = 一场对质新戏。玩家对见证过的事守口与否是玩家自由，泄密的叙事后果由导演排戏处理——世界不会因"玩家知道"自动得知。
- **知情约束 = 单一总纲「角色不是你」（2026-09-09 收敛，原泄密条/知情常识条/即兴角色条三合一）**：编剧案头资料（事件日志、幕后注、世界书）角色本人并不知道；角色开口前须核对话词是否在其自身已知范围内——亲历（事件日志在场者标注）、来历（人物卡）、被告知（剧情内）。派生三特例：①**泄密**——幕后注/私密条目绝不能从不该知道的人嘴里说出（知情者坦白除外，落新事件）；②公开条目「可引用」是上限不是行为——异地角色的外地旧事默认不知（轰动大事可作风闻，鸡毛小事传不出远门）；③**即兴角色**（无卡）只知眼前可感知区，不引用日志旧事。判断由编剧成文时执行（**二级「情节合理性」承载**，判断依据 = 事件日志发生地/在场者/时间标注——**数据做重活，规则讲原理**，不 enumerate 特例）；Actor 路径天然免疫（切片只有亲历与名单内事件）；即兴角色另有结构免疫（无卡无切片无工作单块）。不为公开事件建传播名单、不设入镇时间等状态字段（收刀判据）。
- **NPC 已知集（机械知识边界）**：装配层为每个在场 NPC 机械计算知识清单 = 亲历（全量索引，不随滑窗）∪ known_by 含己 ∪ 听域内公开事件。事件发生地由场景表 `region` 字段（地域词）声明——当前场景无 region = 全域（单区域内容包行为不变）；**一次性布景（location 不在场景表）= 哨兵 adhoc，其公开事件不进任何听域的风闻通道**（宁可不闻不错闻，在场者走亲历通道不受影响）；**NPC 听域由人物卡 `region` 字段（地域词列表）声明（来属地/听域），缺省按其亲历事件推导，推导为空 = 保守（不听说任何公开旧事）**。写手、质检对该 NPC 知识的表述一律以已知集清单为准（旧"近况块"退役并入，写手与质检单一事实源）：跨区域内容包借此实现"异地旧事本地人不知"——新手村的英雄事迹，王都 NPC 一无所知，玩家自报家门时 NPC 将信将疑；同区域轰动事件自动风闻，无需人工打新闻层级；**出差外地人**活动场景在本地、听域仍是家乡，本地的打架名声对其不可见。玩家自经历不丢失（全局日志写手仍可见），边界只画在 NPC 侧。
- **NPC 握有的牌**（"朱明握有王蓉的把柄"）只存在于注入记忆 / 幕后注，是待叙述的真相；何时、以何种方式被玩家发现由导演按戏编排，被发现即落新事件。
- **推论——可引用全集** = 世界概要 ∪ 公开事件条目 ∪ {私密事件条目 \| known_by ∋ 引用者} ∪ {世界书条目 \| 本场导演点名展开}。世界概要常驻每份工作单；公开事件条目与点名展开的世界书条目按装配相关性取用（装配细则见下小节与三章切片）；私密条目按名单。幕后注不进入任何切片，只经"叙述"转为事件后进入引用域；注入记忆以私密条目（known_by = 被注入者）直接进入被注入者的引用域。

### 世界设定 · 概要常驻 / 世界书按需

作者直写的内容包世界设定天然公开、人人可引——与公开事件条目并列为两个公开引用来源。它分**两级**，装配策略不同：

- **世界概要（world_summary）**：作者用几句话框定时代 / 地点 / 基调，并把**硬规则**写死在概要里（"与现实世界无异，没有超自然力量"）。装配时**常驻每份工作单的 system 块、永不裁剪**——LLM 以概要打底、凭自身知识补足细节。概要管"绝不可违背"，人人可引。
- **世界书（lorebook）**：详细设定条目数组，每条 = `{ id · 关键词 · 正文 · 常驻 · 归属 }`（v2：无摘要层）。天然公开但**默认缺席任何切片**——**三条入场通道**：① **关键词触发**（v2）= 零 LLM 关键词匹配，`save.active_lore_ids` 由引擎两处维护（预结算阶段玩家输入命中追加 / 采纳阶段按已采纳正文清空重建，上轮事实优先、上限 5 条去重）；② **常驻**（`always_on`）= 每轮必注入、不占关键词名额；③ **归属**（`subject` = 人物表中文名）= **归属角色在场即注入**、不占关键词名额、每人上限 2 条。工作单按 id 取条目**正文全文**拼入编剧/导演工作单（导演视图同样吃三条通道）。世界书不设 known_by（无访问控制的隐藏设定属幕后注 / 秘密范畴，不是世界书）。
- **NPC 信息 = 人物卡 + 归属条目**（2026-09-13 定稿）：人物卡只在**本人登场**时进装配（在场闸门），所以"他人谈论某 NPC"的场合他的卡够不着；归属条目正是补这个位的容器——他登场时不靠点名就被自动带出，被谈论时仍走关键词通道。**跨界事实一律归条目**（单点存储、不双写），卡里只留一句关系链指针（"父亲朱文武"）作触发桥，不算重复。**一处信息放哪**：卡管"他在场时怎么演"（性格 / 口吻 / 在场行为），条目管"关于他的事实"（可被谈论、可被引用的设定细节）。
- **铁律一：硬规则只进概要、不进世界书**——世界书条目无人点名即不受约束，凡"绝不可违背"必须常驻，否则不查书的工人会写出违背世界观的戏。
- **铁律二：世界书运行时不追加**——作者只读静态资产；即兴补出的世界细节（"镇上其实有家旧戏院"）走叙述落事件流，不回写世界书。

### 元配置 · 全局叙述预设

预设是**全局通用配置**，不随世界资产包走；存于 `data/presets.json`。界面只提供两个大框：

| 成员 | 内容 | 消费方 |
|---|---|---|
| **导演准则** | 自然语言排戏规则，例如“不要主动揭穿秘密”“优先让 NPC 主动制造冲突” | 导演判定 |
| **说书人预设** | 自然语言正文写法，例如文风、描写方式、禁用词等 | 说书人成文 + 质检核对 |

- 玩家在设置面板里编辑这两个大框，保存后全局生效。
- 说书人初稿按说书人预设直接成稿；质检按同一块内容做一致性核对。
- 导演判定按导演准则排戏。
- 原有的 `style / description_style / banned_words / pace` 仍作为内部兼容字段保留，界面不再单独展示。

> **衔接**：各角色读档案的切片规则见三章「发声与视图隔离」；各机制的数据落点在本章——M19/M18 移动与在场产生位置推导依据，M5（二期预留）结算写关系轴并在②自动落账，M16 注入留痕存②，M14 从事件流与导演窗口取目标素材，M1/M18 以①最后事实与②事件推导做推断基线。

### 快速造世界 · 内容包的生产路径（2026-09-13）

内容包此前只有两条入口：手写文件、或"另存为新世界"。前者要一次填全，后者改比填更慢。新的口径是**给最小种子、剩下的边玩边长**——开局 = 新建一个世界（空白种子或一句话草稿），它同时就是你正在玩的存档；开局之后缺什么随手在世界工作台补，改动即时生效。

| 路径 | 输入 | 产出 | 落盘时机 |
|---|---|---|---|
| **L1 空白种子** | 世界 ID / 世界名 / 主角名 / 开局场景 | `world.json` + 1 个场景 + 主角卡 + 空世界书/数值轴 | 点"创建"即落盘 |
| **L2 一句话草稿** | 上述字段 + 一句前提 | 3~5 场景 / 2~4 人物卡 + 主角 / 2~4 世界书条目 / 概要 / 开局白 | **先预览不落盘**；玩家改过、点确认才落盘 |

- **最小可玩的下限**：1 个场景 + 1 张主角卡。缺场景事件无处落，缺主角卡首轮在场名单就空（主角位置由事件流水推导）。
- **开场白是位置事实不是装饰**：它成为新存档的事件日志第一条，也是主角在本世界的第一条"我在哪"记录。留空时引擎写一句纪实句「`<主角>来到<开局场景>。`」，作者随后在工作台概览页改。
- **草稿是提案**：LLM 写的一切在确认前都不算数；过不了引擎体检（`check_world`：主角卡唯一性、`start_scene` 是否在场景表、世界书条目有没有关键词…）就不进 `content/`。
- **手填字段是硬约束**：玩家在表单里写死的世界 ID / 世界名 / 主角名 / 开局场景优先于草稿，冲突时以表单为准。
- **世界列表读世界名不读目录名**：列表显示 `world.json` 的 `name`（如「青石镇」而非 `qingshi2`），并带体检结论（待修的列出问题）。
- **校验随时可点**：`check_world` 从 CLI 专用变成世界列表上的一个按钮（此前保存是静默的，场景 id 重复、主角卡漏了、`start_scene` 打错字全不报）。

### 世界工作台 · 作用域与保存口径（2026-09-13 重构；同日改单一真相源）

**世界=存档 1:1，单一真相源**：世界列表列的就是正在玩的各世界（点「打开」接着玩，带时钟进度），没有模板/副本两层。想保住初始状态，开局时「导出资产包」存到自己电脑；改坏了就删掉世界、导入资产包得到初始态新世界。全套口径：

- **就地编辑，无编辑模式**：资产页直接是表单，保存即时生效（写的就是世界目录本身）。
- **保存条写明落点**：底部常驻「所有改动直接保存到这个世界，即时生效」；未保存改动时显示 ● 标记 + 待修数，关闭弹窗有拦截，tab 切换不丢改动。
- **两级保存闸门**：不变量（恰好一张主角卡）失败 → 硬拦 400、什么都不写；语义问题（`start_scene` 不在场景表、场景 id 重复、世界书缺关键词、归属角色不在人物表、同一角色归属条目超 2 条）→ 保存成功但当场列出问题（软警告）。
- **三组动作**：备份与复制（导出资产包=纯资产快照 / 复制为新世界=fork）· 全量备份（资产+事件日志一起打包，导入时若该世界已在玩则 409 拒绝、绝不覆盖）· 危险区（重置剧情=只清事件与运行态，世界资产不动）。
- **上下文常显**：标题行写「世界名 · 目录名」，杜绝"我在改哪个世界"的困惑。

> **衔接**：本节的产物就是〇章的①人物卡 / 世界设定 / 场景表；转正类需求（即兴角色建档、包外地点注册）见三章「即兴角色三机制」与 M17——两类转正的落点都是**世界工作台**，不走导演窗口（见三章「角色清单与账本纪律」）。

## 一、时钟与空间（M20 / M17 / M18 / M1 / M19）

### M20 · 时间推进：全交审计（2026-09-16 去规则化）

**一句话**：时钟在**采纳那一刻**由审计一次性结算——玩家给了具体时间就按玩家要求，没给就由审计自行估计剧情推进多久，只向前不倒退。

- **结算点唯一**：时钟只在**采纳**候选时推进（`Transaction.commit`）。写轮只产出候选，不写账本。
- **优先级链（两档，delta 只可能被加一次）**：
  1. 审计 `clock_to` —— 玩家输入或正文**明确给出时刻** → 绝对对钟（格式坏或早于当前时钟 → 拒绝并留痕）；
  2. 审计 `delta_minutes` —— **自行估计**这场戏实际跨了多久，夹进 `[0, 1440]`（24h 保险丝）；
  3. 都不给 → 不推进。
- **时间是审计的独家职责**：规则侧的跳时解析（日界词 / 时辰词 / 相对天数 → 绝对时刻）已于 2026-09-16 **整条删除**。原因是那套词表用正则匹配自由语句，克制规则越补越多（"没等到明天就走了""三天后我才明白""直到我有一点累"都会被误判），且它一旦先定钟就必须再经 `settle_hint` 通知审计"别再估"，凭空造出跨工位重复计费的风险。审计本来就同时看得到正文与玩家输入，是天然的结算方。
- **判定模型 = 估这场戏的时长**：以**玩家经历了什么**为准自行估计，不问文本里的时间词（"明天见""你昨天答应的"给 0）；纯闲聊、原地续聊给 0。**提示词里的时长举例已删除**（样例上界会诱导模型把复合活动压成单一类别："吃饭+劝酒+同睡+脱衣"被估成 60 分）。
- **时间只向前**：提示词按去否定化写"只向前不倒退"；引擎另有方向守卫兜底（`clock_to` 早于当前钟 → 拒；`delta` 走 `max(0, …)`）。
- **移动仍由规则预结算**（与时间正交）：`第二天去学校` 的"去学校"照旧在规则侧解析目的地，时间则完全交审计。
- **结算留痕**：每次结算的起止时钟、依据档位、审计估了多少、是否被保险丝截断、对钟是否被拒 → `save.json.last_settlement`，顶栏时钟 hover 可见（老存档里的规则档字段按缺省处理）。
- **叙事时间与世界时钟分轨**：天色 / 气氛描写可自由流淌；要真正推进时间必须走上面的结算（正文写明的到达时刻由审计以 `clock_to` 给出，优先级最高）。
- **离线状态**：时钟只在有输入回合时推进；存档离线期间世界时间停留在最后推进时刻，重开时从该刻续走。
- **世界钟起点 = 内容包资产**：`world.json.start_time`（ISO 时间，可选）声明该世界的开局时刻；新建存档与重置存档都回到此起点（缺省回退引擎默认 2026-07-14T08:00:00）。作者改一个字段即可让世界从任意时刻开局。
- **世界起点的用途已收窄**：只作存档起点。原"次日默认钟点取自 start_time 小时 + 06–11 窗口守卫"的机制随规则跳时解析一并删除——"第二天早上"落几点现在由审计按常识判。

### M17 · 场景注册表与双轨生成

**一句话**：地点 = 预置为主、现场补全，补全即注册、可复用。

- **预置（骨架）**：内容包 `scenes.json` 写死常驻地点。场景节点属性 = `id（中文名，同时是显示名）· aliases（变体名）· perceivable（可感知区）· region（消息域）`。
- **现场补建（转正）**：玩家走进包外地点（"街角新开的奶茶店"）→ 采纳时由审计给出 `location` + `scene_name` 并置 `register_scene=true` → **只记进运行态候选册 `save.locations`（`status=pending`），不写资产**；玩家在左栏「待落卡」→ 抽屉「落卡」页核对后点确定，才写入世界目录的 `scenes.json`（单一真相源），之后可复用、可被 NPC 提及。（2026-09-19 改判：此前是采纳那刻直接写表。）
- **落表内容只有名字 + 玩家填的描述（2026-09-19）**：候选册累积别名（同轮 `scene_name` 与后续各种叫法都进 `aliases`，下一轮靠它救回，不会排成两条）；落卡时 `perceivable` 由玩家确认（草稿由模型从该地点的原文总结，可改；**留空 → 占位句 `SCENE_PLACEHOLDER`「暂无描述。」**）。审计仍是提取式工位，**不给场景编描述**。纠偏 `_resolve_scene` 与 `resolve_destination` **解析域 = 场景表 ∪ 候选册**（id 优先），所以**没落卡的地点也走得通导航**。
- **一次性布景**：只去一次的剧情地点（密室/郊外旧楼）按剧情使用（`register_scene=false`），只记事件条目的 `location_name` 显示名、不进导航集，事件流仍可回溯引用。**在落卡窗口点 × = 定为临时**：进 `dismissed` 静音、不再自动入队，别名仍留在册里供解析。
- **推导锚点**：NPC 位置推断（M1）、导演取景编排全部锚定注册地点与可感知区。
- **转正判定：来源定初态 + 引用信号驱动**。
  - **初态由来源决定**：玩家声明的地点（"走进街角那家奶茶店"）一律**入候选册**（解析域含候选册 → 当轮就找得到路，但资产层等玩家拍板，2026-09-19）；导演排戏捏的舞台默认临时；编剧写景顺笔的地点（"巷口有家旧书店"）视为装饰性文字。
  - **转正信号（引擎被动核对）**：① **玩家回访 / 指代**（"回刚才那家奶茶店"）——最强信号；② **剧情目标指向 M14**（该地点是某目标的节点）——未来引用概率高；③ **导演/NPC 复用**（下一场戏再用此舞台 / NPC 拿它当惯常地）。任一信号出现即**入候选册 `save.locations`**（`status=pending` → 左栏「待落卡」列出来）。**入册 ≠ 落表**：写 `scenes.json` 只有一条路 = 玩家在落卡窗口点确定（`POST .../locations/{name}/file`）。
  - **成员资格**：注册地点才进入可导航地图与 M1 位置推断候选集；未注册地点的事件引用仍在事件流内可回溯。
  - **导演可预注册**：排戏时预知舞台会复用（如安排成某 NPC 秘密据点）→ 走 `POST /sessions/{sid}/locations/{name}/file` 落卡（**导演不再有直接写 `scenes.json` 的口子**，2026-09-19）。
  - ⚠️ **邻接图 / 开放时段已退役**（2026-09-10）：场景之间没有边，也不再有开放时段字段，"从 A 能不能到 B"不再校验。

### M18 · 位置与在场者

> 注：位置/在场没有独立位置表，均由统一事件流事件（`location + participants`）推导。

**一句话**：谁此刻在哪、谁在当前场景，由事件流事件推导直接给出。

- **查询规则**："X 此刻在哪" = X 最近一条带地点且包含 X 的事件；"谁在当前场景" = 最近事件中地点为该场景的实体集合。
- **场景 = 该地点的在场实体集合 + 可感知区**（M17 节点）。世界惰性渲染：场景在玩家到达或询问时才生成描述。
- **位置 = 事件推导**：事件记录携带 `location` 与 `participants`；某实体在某事件中出现，即表示“那个时刻他在那”。旧事件随世界钟自然成为历史锚点。
- **过期降级为推断素材**：历史事件成为锚点（"三天前在网吧"），查询回退到"上次事件 + 时间差 + 人格隐含大框"上推断。
- **空档位置查询 · 三件套**：① 最后一条相关事件；② 人格隐含大框先验（"开店"类日常场所，来自人格格的身份定位资料）；③ 时间差。引擎合成"此刻他在哪才合理"的候选域 → 导演在域内做叙事落点（网吧 = 通宵惯性；家 = 宿醉补觉；被禁足 = 覆写 + 现编解释，见 M2 故事道），玩家进门那刻的在场结算对导演落点执行——导演拍板本身落一条新事件。
- **覆写 = 统一事件**：导演/玩家覆写 = 写一条统一事件（如“朱明在网吧。”）；该事件优先于旧事件与推断。
- **离场去向**：NPC 离场后停在最后事件；有人进场/询问时若该事件已过时，按空档三件套重推。
- **未来时刻位置**：位置的写入时机 = 结算 / 覆写当场。导演排"某日他在某地"的戏份时当场落一条事件或事后排一场戏，账本随结算成长。

### M1 · NPC 动态位置推断

**一句话**：NPC 此刻在哪 = 按「最后事实 × 时间差 × 人格隐含大框 × 地点标签」推导出的候选结论，供目标解析与导演排戏取用。

- **触发**：玩家说"去找朱明"但没说去哪；导演排戏需判断某 NPC 此刻可能在何处。
- **核心设计**：① 事件流事件（M18）提供最后位置与覆写 ② 场景注册表（M17）提供场景别名与可感知区 ③ 时间差。2026-09-05：正常日程字段已移除，习惯先验不再引擎级建模——候选域由最后事实 + 人格隐含大框（"开店"类日常场所，资料在人格格）合成，他是否真在那由导演按叙事拍板（M18 空档三件套）。

### M19 · 移动解析与场景切换裁决

**一句话**：玩家去哪由意图解析决定（玩家叙述优先），引擎执行裁决链。

- **目的地解析（实际只有两路，`rules/movement.py::resolve_destination`）**：① 地点直命中（"去网吧"→ 场景 id / aliases / **候选册别名** 子串表）；② 由人推位置（"去找朱明"→ M1 的最近位置事实）。都未命中 → 返回 `None`，location 与场景**候选**交采纳时的审计从正文判（未注册的新地点由审计给 `scene_name` + `register_scene=true` → **入候选册，不写资产**，2026-09-19）。
- **NL 判断边界**：自然语言只在规则预结算（**只剩移动意图**，时间已交审计）这一处被判断；其后在场结算全走规则 + 账本。
- **裁决链（2026-09 两次退役之后）**：移动意图（`looks_like_move`）→ 目的地解析 → `rule_bundle.destination` 作为编剧工单的场景 → 到达后的位置事实 / 在场 / **地点候选册**（`register_scene` 只入册，不再落表）由审计与账本推导。
- **邻接图与耗时表已退役**：2026-09-10 起不再查可达性、不再算路程，"移动要多久"一律归审计估时长（`delta_minutes`）。
- **移动粒度**：A→B 场景直达、一步结算。
- **移动与时间互不干扰**：`第二天去学校` 的目的地由规则结算、时间由审计结算（历史 bug：单标签路由让跳时吃掉移动预结算；那套"两件正交事实"的规则设计已于 2026-09-16 去规则化）。
- **场景描述 · 模板优先**：常规到达 = 引擎按 M17 场景属性（别名 / 可感知区 / region）拼静态底稿，尽量零 LLM；首次到达新场景 / 剧情舞台 / 需特殊氛围的地点，导演升级派编剧按叙述预设专门成文。
- **混合句 · 编剧一把抓**：一条消息含多个意图（"去网吧找朱明，问他打架的事"）→ 引擎先预结算规则段（目的地解析；时间交审计）作为编剧输入，编剧把移动与对话作为**同一场戏一次判定**——衔接顺序（先到后聊）由编剧编排，正文一次成稿。

## 二、信息边界：玩家声明、记忆与注入（M2 / M16；秘密与 known_by 规则在〇章）

### M2 · 玩家叙述优先 / 世界状态覆写

**一句话**：玩家声明的世界状态即事实、立即落库；状态的"理由"在出口时现编并实体化。

- **触发**：玩家说"朱明在家睡觉没起床"，与 M1 推断（网吧）冲突。
- **事实道（实时）**：声明直接落一条事件流事实（位置/世界状态，写操作），调度、他人查询全以此为准。
- **故事道（理由惰性）**：账本只存事实；待该 NPC 被撞见且玩家疑惑/追问才现编解释（"前几天刷夜被抓，我妈不让出门"），说出口即落库为事件（私下情境 → 私密条目 known_by=[该NPC, 玩家]；注入纪律见 M16）。
- **最小世界侵入**：解释尽量复用既有实体与事件链；需要引入第三方（"他爸"）时同步建档入流，先浅后深、追问才往深编。
- **位置衔接**：覆写 = 落一条统一事件（如“朱明在网吧。”），该事件优先于旧事件/推断（见 M18）；后续新事件自然更新。
- **冲突处理**：玩家声明的世界状态即事实，无论与既有事件是否一致都直接落账——一致与否由玩家自决（玩家是作者，引擎不做矛盾仲裁）。

### M16 · NPC 记忆注入

**一句话**：人设永远写不全，剧情需要补背景时走两条纪律分明的路。

- **作者注入**：作者写内容包 / 编辑 NPC 卡 → 直接改数据，无运行时风险（本质是写卡）。
- **运行时注入**：LLM 剧情中补全 → 登记落库进 NPC 档案。三条纪律：① 注入内容与已叙述事件保持一致，确需修正时登记为修正并留痕；② 注入即登记，之后引用系统对得上账；③ 涉密补全 = 登记为被注入者的记忆条目（私密条目，known_by = 被注入者）——玩家与无关者的切片里没有这条；真相待玩家撞破 / 查出，叙述即落新事件。
- **本质**：未叙述的真相可以后补进档案；出口（被说起）即固化为正式事件——补全内容与已叙述事件保持一致（纪律①）。

## 三、角色纪律：导演方案（叙述架构）

> 源头问题：任何"全知大脑"代笔角色都可能说出不该知道的话。本组纪律定两件事：**决策可多脑**（导演拿主意、Actor 演深抉择）、**文字唯一 + 必经质检**（说书人动笔、质检员把关）。

### 角色清单与账本纪律

架构总纲：**记忆全部收进账本（引擎数据库），Agent 全是无状态工人**——开工前引擎现配"本轮工作单"（小且固定），干完写回、转身即忘。状态是输入（每轮新鲜装配置顶）而非要求维持的输出；存储永远是账本的活，Agent 只回写"变了什么"。

| 角色 | 职责 | 调用 |
|---|---|---|
| **导演**（决策中枢） | 判断本回合"戏的走向"：玩家输入已成文 → 核对节奏后采纳；不完整 → 判定缺什么、从账本取料补全（人设×情境决定 NPC 反应方向）；空泛 → 按**玩家所设**节奏档自由编排。产出分层剧本指令，正文由说书人成文 | 每回合必经 |
| **NPC Actor** | `has_actor` NPC 遇深抉择（内心判断 / 涉密反应 / 是否信任）时以自身视图隔离决策 | 触发 +1 |
| **说书人** | 把剧本指令写成正文——唯一正文笔 | 需成文时 0~1 |
| **质检员** | 必经前置文字关：文风把关（按叙述预设核对/润色）+ 泄漏比对（见本章末条） | 每回合必经 |
| **世界审计** | 采纳时提交后结算：时间推进同步 / 关系结算（二期）/ 目标完成判定 / 生命周期扫描 | 采纳时同步 |

- **回合调用账**：导演(1) →〔说书人(0~1)〕→ 质检(1) 串行必经；NPC Actor 触发 +1；世界审计在采纳时随提交后结算完成。**感知延迟 ≈ 2~3 跳**——质检必经是玩家拍板（质量优先于延迟），降本靠：质检用辅助模型 + 局部改写（只动需改句，整段无恙原样透传）。**辅助模型还可以走另一个出口**（2026-09-20）：主模型用付费 API、辅助模型指到本地模型，是这个功能最直接的省钱用法——两者各有一套 base_url / api_key，在「设置 → 辅助模型接口」里配。
- **回合流水线三保障**：状态外置（模型靠账本供料）、工作单每轮现拼（小且固定）、写回账本走 schema 校验——多 Agent 的价值 = 视图隔离。
- **记忆条目 = 引擎规则化拼接**：把已记账的结构化字段（时间 / 地点 / 行为类型 / 在场者）按固定模板拼装成条目（时间+地点+谁干了什么+在场者），LLM 的唯一参与 = 补一句**定性附注**（"她语气不对劲"）。条目原料只取已记账字段——每轮概貌稳定、成本确定。

**导演窗口（OOC 戏外工作台）**：仅玩家主动开启，导演纯被动。窗口内所有话都是**戏外话**——玩家说了 ≠ 主角在戏里说，导演的话 ≠ 正文。窗口产出三态：给建议 / 答疑问 / 改账本：

1. **求建议**（玩家没创意）：导演扫 M14 剧情目标 + **当前叙事张力**（关系状态、节奏档、未推进的目标）现排 2~3 个建议——既收尾型（"该去赴约了"）也**推动型**（"上去抱住她"）。
2. **答疑**（玩家忘事）：如"王蓉喜欢什么？我答应过她什么？"→ 只读账本简略回答（NPC 档案 / 事件流 / M14 台账）。
3. **剧情讨论**（双向磋商）：商量下一步怎么更合理 / 更有张力 / 更合玩家偏好 → 聊定后导演给一段**简略输入建议**，玩家复制进正文输入框执行；玩家表达的叙述偏好（节奏 / 文风 / 描写方式）→ 到〇章「元配置·叙述预设」设置里调整，导演只按玩家最终设置执行。
4. **幕后事务**（账本操作）：
   - **静默覆写 / 调遣**："朱明明天去夏令营"→ 导演直接落一条统一事件（source=director）+ 给该时段排一段戏（时间推进随该段戏按玩家声明跳时结算，见 M20），正文以"已发生"为基演出。位置随导演排戏当场落账，随结算成长。
   - **角色档位调整**：不在导演窗口操作——配 / 取消 Actor 由玩家直接在世界工作台编辑人物卡（`has_actor` 字段）；人物卡厚度不足时先走补卡事务。
   - **事件访问改判**：玩家回看事件日志，认为某事件初判公开/私密有误 → 要求导演按〇章「访问状态改判」处理（改判私密 = 名单由导演直接给定落账，不做检索起草——改判即玩家接受"已传开者收不回"的逻辑代价；改判公开 = 清空名单恢复公开；官宣类公开化走排公开新戏承载）→ 确认后只改访问状态、正文不动。
- **扶手规则**：一切建议在玩家**采纳**（复制 / 确认）后执行。观察 / 打量等描写请求在**正文窗**输入，走正常正文流水线（导演取 人设×状态×情境 → 说书人成文 → 质检）。

**NPC 决策二分归属**：轮到 NPC 反应 / 决策时——**有 `has_actor` → 决策需求派发给其 Actor 自主决定；无 → 导演代笔**（无专属 Agent 的人物通常重要性不足，泄漏面小，由质检兜底）。

- **上缴即停笔 → 必有第二稿（2026-09-11 修复）**：编剧判定深抉择后会**把那一拍留空**（实测：只写吃早饭和发问的引子，NPC 的反应根本没写），所以只要出现上缴，引擎必定回炉第二稿——可派者附 Actor 决定，不可派者（无票 / 不在场 / npc_id 无法识别）明说"由编剧直接拍板、不要把这一拍留空"。**任何上缴都不会被静默丢弃**，稿子永不悬空；可派门槛 = 在场 ∩ 配 Actor。

- `has_actor` 是**运行时档位**，初值落卡（〇①）：作者内容包预标重要 NPC；即兴角色转正时决定（深聊对象默认配）。Actor 是储备——日常浅反应导演照旧代笔，深抉择才派活。
- **角色档位（2026-09-05 简化）**：配 Actor 与否由玩家直接在世界工作台编辑人物卡（`has_actor` 字段）管理，不经导演窗口。玩家可随时配 / 取消；人物卡厚度不足时先走补卡事务；功能性发声（招呼 / 跑腿 / 敷衍）属模板层走话术模板。原"点名强制档"（浅反应也派）已取消——浅反应一律编剧代笔。
- **升格通道（单向升档）**：角色重要性上升（路人的王蓉开始恋爱 → 深抉择变多）时，规则给信号（关系轴升温〔二期信号〕 / 连续深聊 / M14 目标挂账）→ 导演在幕后事务判定升格（改一个标记位，正文随之演她越来越像自己）。无戏份 = 深抉择零触发 = Actor 零调用零成本；永久退场走〇章 `retired` 状态位。
- **升格触发补卡事务**：升格后人物卡厚度不足（性格可细化 / 说话风格不够 / 前史空白）→ 走 〇章① 补卡事务：在世界工作台直接编辑该卡；也可从左栏「待落卡」入口落卡（**模型从已采纳正文里总结 外貌/人格 当草稿，带「AI 草稿」标记 + 原文证据并排，玩家核对后点确定才落盘**——2026-09-19 收窄旧口径"只机械提取、引擎不代笔"；**不可推导的字段仍由人写**：幕后注 / 自知的隐秘正文没写，不进落卡表单）。
- **浅反应导演编排、深抉择派 NPC 自己演**：脸红低头这类表象反应导演直接排；"是否背叛你"这类内心深水区须派 Actor。
- **导演交付物分层**：剧本指令分**可见层**（脸红 / 低头——正文只写这层）与**动机层**（暗恋——只进账本与后续剧情参考）。导演读幕后注与未叙述真相是安全的——导演产出物只到剧本指令层，正文一律由说书人成文；闸口在分层交付。

### 发声与视图隔离

按"有无 has_actor × 是否深抉择"分执行档：

- **V0 功能性发声**（招呼 / 跑腿 / 敷衍）：话术模板 / 规则，尽量零 LLM。
- **代笔路径**（无 has_actor，或 has_actor 的浅反应）：导演排、说书人写。
- **Actor 路径**（has_actor × 深抉择 × 触及受限区）：派发 Actor，上下文**物理隔离**——Actor 输入只含 persona、自己的记忆切片、引用域内的可引知识（公开条目 + known_by 含自己的私密条目）+ 本场 directive 点名展开的世界书条目。信息密度是天然防护——无知识性台词的角色永远安全。

### 即兴角色三机制

AI 可能现场捏角色（乞丐），其档案 / 视图 / 引用权在到场那一刻全部空白——无切片者，公开条目与私密条目都不装配给它。对策：**知识只能经给料边界进入角色的嘴**；**人格档案只能经玩家拍板进入引擎**。

1. **给料即资格 · 可感知原则**：有切片者（预注册 NPC / 玩家）自带切片知识开口；无切片者（即兴角色）台词只引用 scene 可感知区里的内容（可感知描述、当前可见之物）。scene 只放可感知描述——处理现场干不干净成为有 gameplay 后果的行为。
2. **获键：引擎认人（2026-09-19）**——**有名字**且与玩家**往来累计 ≥2 轮**（不要求连续）的人，引擎给他一个**键**：他从此以自己的名字进在场名单，工作单里标为「临时角色」并明令编剧**不许替他编前史 / 来历 / 人际 / 动机**（编出来的内容会伪装成事实）。**没名字的人（酒保 / 伙计 / 摊主 / 路人）永远只是即兴角色**，戏份多少都一样——"没名字就无从落卡"，职能称谓也不该当史实里的名字（键即中文名，同名会把别人的事算到他头上）。键是**运行态**（存 `save`，随世界重置清零；卡是资产，不动）。这一条填的是此前的空洞：在"酒保说他叫卢克"以前，他既进不了在场名单、也无从转正，**采纳即蒸发**。
   - **边界只有这一条**（有名字 + ≥2 轮），不按"是否被点名 / 是否自报姓名"这类文本特征加规则——自由语句的正则匹配必然越补越多。
3. **落卡：玩家拍板（建档转正）**——未落卡的人**看得见、挂得住**：左栏在场名单里带「未落卡」标记，下方一行「待落卡 · N」入口（N = 人物数 + 场景数，N>0 才出现）→ 抽屉「落卡」页列出**全量**（含**不在场者**：玩家离开酒馆后他还挂得住，否则这个人就只在存档里躺着、看不到也操作不了）。逐条：
   - **收起态只有一行**（名称 + 展开 + ×）；展开才去要草稿、才发请求（没展开的条目不花钱）。
   - **AI 草稿**（2026-09-19）：模型从**已采纳正文**里总结出 外貌 / 人格。三条防线见上一节；草稿只是**预填**，玩家改过以玩家为准。
   - 「已写出的事实」= **默认折叠**、点了才拉：已采纳正文里关于他的原文（一段证据，不是结论）。它是草稿的**对账凭据**——草稿与原文并排，玩家才能逐句核对。
   - **确定落卡** = 把这两栏写进人物卡。落盘走的是资产编辑那条路（`check_assets` 闸门 + `save_world_assets`），**不新增第二条写世界的路径**；落成后名字从运行态移除（键交还给卡），他成为有卡角色，此后 has_actor / 归属条目 / Actor 切片照旧。幕后注 / 自知的隐秘 / Actor 档位不在落卡表单里——**落卡后到工作台补**（"最小需求"正好等于"可从正文推导"的子集）。
   - **放弃（×）**：他退回去当即兴角色。**必须同时清零出场计数**——否则下一轮一出场计数仍 ≥2，立刻重新获键，撤销形同无效（与「同一个结束不能记两次」同源）。
   - **入口不是导演窗口**：本项目实测——M14 目标与状态增删改的唯一入口都曾放在导演窗口，而四个世界的 `goals` **全是 0**、`entities` 0/0/0/1。**别再赌第二次**：落卡入口在左栏（"人"的地方），与「世界工作台」同一个真相源。
   - **已知缺口（未做）**：旧「转正仪式」还要求**初始引用权**——即兴角色登场时亲历过的私密事件（"他见过满身是血的你"），本应在他转正时补进那条事件的 `known_by`。当前私密知识按成员挂账、`access_overrides` 是唯一权威表达式，而落卡**不会回填历史私密事件**。这是缺口，不是已实现。

### 地点候选：新地点也是"引擎只给候选，玩家拍板"（2026-09-19）

**问题**：新地点此前由审计**单方面静默注册**——采纳时 `AuditOutput.register_scene=true` 就直接写 `scenes.json`，而描述只能是占位句「暂无描述。」，那句还**每轮都被注入**。资产层凭空多出一个没描述的场景、且没人被通知去补。人物侧早就有闸门（引擎只给键、卡必须玩家落），场景侧没有——**这个不对称就是隐患**。

1. **入册，不落表**：审计判"玩家要去 / 回访 / 会复用"的地点 → 进 `save.locations`（运行态候选册，`status=pending`），**不写资产**。`register_scene` 的语义从"注册"改成"**建议落卡**"。
2. **别名累积**：历轮审计给的变体名攒进同一条目。解析域（`_resolve_scene` 纠偏 / `resolve_destination` 寻路）**必须并上候选册**——否则玩家还没处理的"老巷旧楼"，下一轮会被当成新地点，队列里排成同义重复的两条；且"去老巷旧楼"会走不到规则寻路，等于把目的地的决定权让给 LLM。
3. **落卡：玩家拍板**——表单只有**描述**（`Scene.perceivable`）一栏；**名称是键、只读**（改名会让所有历史事件的 `location` 落空）。该栏先由**模型从"发生在这个地点的已采纳正文"总结一份草稿**预填（带「AI 草稿」标记 + 原文证据并排可对账；**无证据则不调 LLM**），你核对修改后点确定。别名一并写进 `aliases`。描述留空 → 占位句（与旧行为一致，区别是这次是**玩家看着空栏点的确定**）。落盘走 `check_assets` + `save_world_assets` 同一条写路径。
4. **⚠️ 落卡会改变听域语义，必须让玩家看见**：未注册地点 = `adhoc` 哨兵（公开事件**谁都不风闻**）；落卡后 `region` 留空 = **全域公共区**（**所有人风闻**），且**追溯生效**（`_event_region` 查表现算）。窗口里写明这句话；要设听域请落卡后到工作台改。
5. **× = 定为临时**：进 `dismissed`，**不再自动入队**。与人物侧**故意不对称**——人物的键靠"累计 2 轮往来"重新挣回来（真实信号），而场景的 `register_scene` 是个 boolean、**每访问一次就重发一次**，不静音的话玩家每次回到那儿都要被问一遍（M14 类失败：入口惹人烦 → 玩家绕开）。别名仍留在册里（解析域照旧认得它），要改成正式场景去工作台。
6. **审计提示词**同时列出候选册（标「待落卡」/「已定为临时」），让它**沿用同一个中文名**而不是自造变体。

### 质检员 · 必经前置文字关

说书人初稿（或导演直接采纳的玩家原文）**一律过质检才送达玩家**：文字修饰 / 文风一致性 + 泄漏比对一次完成。送达即进入**候选区**——质检管"够格呈现"，玩家采纳那一刻才落账成史实（见下「玩家采纳 · 回合事务」）。

- **输入两区**：正文初稿（可改）+ 受限知识参照区（只读比对——参照区内容与正文成品分轨，成品只取初稿与改写）。
- **泄漏命中 → 脱敏改写**（模糊化表述）。
- **矛盾不设引擎仲裁（2026-09-05 拍板）**：剧情走向与既定设定的一致性是**玩家的判断**——看得出矛盾玩家自己处理（重掷 / 放弃 / 导演窗口覆写），看不出说明其不重要。质检不设矛盾分级、不挂队列、不提示。文风依据 = 〇章叙述预设：编剧初稿按预设·文风与描写方式直接写；质检按同一预设做文风一致性核对 + 禁用词硬拦（命中即改稿）。预设是每轮装配的输入，玩家覆盖对**后续轮**生效。
- **文风依据 = 〇章叙述预设**：说书人初稿按预设·文风与描写方式直接写；质检按同一预设做文风一致性核对 + 禁用词硬拦（命中即改稿）。预设是每轮装配的输入，玩家覆盖对**后续轮**生效。
- **泄漏 = 剧情错误**（OOC 子类）——每个 LLM 都知道它会被查。

### 玩家采纳 · 回合事务（落账闸门）

**一句话**：一回合 = 一个事务。正文过质检送达玩家后仍在**候选区**，玩家从候选版本中选一份采纳（显式，或只有一份时的下一次输入自动采纳）那一刻才整体原子落账——质检管"够格呈现"，玩家采纳管"算已发生"。

- **候选区**：送达 → 采纳之间，该回合的**多个候选版本**（初稿 + 各次重掷结果）与**全部账本副作用**（时钟推进 / 位置变化事件 / ② 经历 / known_by 初值）一并暂存，账本零写入。重掷/抽卡只新增候选版本，不删除旧版本。
- **下一次输入 = 默认采纳（仅单候选时）**：若当前只有一份候选，玩家不点“采纳”直接提交下一条指令时，引擎先把该候选整体原子提交，再进入新回合；不打断玩家连续操作。若当前有多份候选，玩家必须先选择采纳哪一份，引擎不自动替玩家选。
- **采纳 = 原子提交**：从候选版本中选中的正文成事件条目，副作用一次生效，回合闭环；提交成功后清理该回合其余候选版本。
- **放弃 = 整体回滚**：明确放弃当前回合时，该回合全部候选版本一并清理，账本无痕——同一回合不会留下"两版都发生过"的时间线分叉。
- **重掷三档**（玩家对已送达候选不满意时，每档生成一份新的候选版本，旧版本继续保留供比较）：
  - **换说法**：同一份剧本指令，只重跑说书人换写法——廉价，适合"写得不够味"。
  - **换走向**：导演重排整场戏、决策重判——全链重跑，适合"这反应不对 / 戏不该这么走"。
  - **定向重掷**：玩家口述不满处（"别让他这么快坦白"），导演按意见改——一次命中；导演窗口可对话，定向优先于盲抽。
- **采纳后 = 史实**：此后反悔走导演窗口（访问状态改判 / 覆写），与候选区重掷分轨——导演窗口幕后事务同此闸门：玩家提出、确认后落账。
- **叙述的定义钉在采纳上**：候选稿只是提案，玩家否决即不成立（玩家是作者，作者否决不构成已叙述事实）——与"叙述即公开"同一条铁律，账本只收玩家最终采纳的那一份正文。

## 四、对话 · NPC 主动 · 玩家引导（引擎侧留存）

> 编排决策（何时专注、谁主动联系、给什么建议）全归三章导演；本章只留引擎必须持有或执行的部分。

### M5 · 选择分支与关系值结算（暂缓二期）

> **状态**：本机制与〇③ 抽象属性轴一起暂缓，二期再设计。v1 不实现关系轴数值结算；关系进展由导演按事件流叙述体现，面板无数值栏。以下为二期设计基线，保留供后续设计。

**一句话**：选择分支结算关系轴数值，变化原因自动留痕。

- **触发**：王蓉求助修电脑，帮/拒。
- **结算落点**：分支判定 → 命中〇③ 关系轴（标"记因"的轴）→ 数值更新，并自动在 ② 落一条账（谁 · 因何 · 影响谁 · ±多少）——日后王蓉态度变了，系统与玩家对得上账。

### M8 · 节奏档 · 引擎侧执行

**一句话**：叙事节奏 = 玩家可调的节奏档（档位值存〇章叙述预设）；导演在档内判戏，本条只留引擎必须执行的机械部分。

- **档位归玩家**：快节奏 / 慢节奏等档位是玩家的偏好输入——设置入口随时自选、随时可改，默认档由内容包给、玩家可覆盖；导演"节奏感"的唯一依据 = 玩家当前所选档位。
- **导演在档内排戏**：档位框节奏幅度（快 = 事件流速高、琐碎日常少；慢 = 细描日常、多驻留细节）；对话聚焦（"这段戏专注双人、事件缓发"）、放权快进等切换由导演按戏情判定——档位边界玩家划、档内切换导演判。
- **引擎侧执行**：① **事件暂停**——档内离场/偶遇/推进类戏份缓发，玩家出的题仍走流水线；位置覆写与时段编排在档内挂起，切出档后由导演决定是否补排；② **上下文收敛**——装配收敛到「当前场景可感知 + 对话对象 + 关键历史状态」，世界其余留在账本（分层检索）。
- **关联**：对话回合时钟冻结（M20）；放权快进 = 玩家声明跳时 + 导演编排时段戏（该时段世界发生了什么由导演排、说书人成文，时间推进随玩家声明跳时结算，见 M20）。

### M12 · NPC 主动联系 · 主动登门

**一句话**：NPC 主动联系 = 导演的**主动性排戏开关**——当前没有更重要的事件需求时，安排 NPC 主动找上玩家，作为在场戏走正常流水线。

- **触发时机（导演判）**：当前没有重要事件需求（主链无事可推、玩家没在追事、或关系线 / 目标该冒头）→ 导演挑 NPC、挑由头安排她主动登门。节奏该推（M8）、目标待推进（M14）是主要排戏依据；NPC 卡的"主动倾向"是人设素材。
- **呈现 = 在场戏，不是离线消息**：本作没有"离线时段"——时钟只在玩家输入回合推进（M20），玩家不在场事件流不留账，NPC 发不出"你不在时"的消息。主动找你 = 导演在当前回合排一场**她找上你**的戏（登门 / 路遇 / 同场偶遇 / 托人带话），由说书人成文、走正常流水线（质检 → 候选区 → 玩家采纳才落账）；可及性由导演按空间常识照应（NPC 须能出现在你的地点或邻接点）。
- **决策归属**：谁主动、何时、以什么由头与方式 = 导演按节奏档 + 人设 + 目标台账排；有 has_actor 的 NPC 遇深抉择可派其 Actor（见三章）。

### M14 · 剧情目标（主线载体，2026-09-07 取代开放钩子台账）

**一句话**：玩家在导演窗口设立剧情方向（大目标=主线 / 小目标=支线），编剧写作时向目标自然引导，审计在采纳时判定目标完成。

- **设立**：玩家与导演 OOC 商量 → 导演回 set_goal action（text / kind: big|small / subject? / big_goal_id? / npc_id?）→ 玩家确认 → 落 save.goals；废弃同理（status: abandoned）。
- **两级语义（2026-09-12 落地，`big_goal_id` 从此真正参与运转）**：**大目标 = 章节**（这一段故事往哪去，只给方向）；**小目标 = 节拍**（这一章里一个可验证的节点，就是"下一步该发生什么"）。小目标用 `big_goal_id` 挂到大目标下，层级只允许一层（大目标不接受挂靠）。**额度按层级分档**（不再是全局 6 条共享）：大目标 ≤2 条、单个大目标下子目标 ≤3 条、未挂靠支线 ≤2 条——子目标额度**按父计数**，挂到主线下面才能多挂（上限本身成为引导玩家用父子结构的压力）。完成一个子目标即腾出名额（滚动释放）；挂靠对象必须存在、是大目标、且未闭合。
- **归属者（subject）**：目标不限于主角——`subject` 为**空串**（默认，主角自己的目标）或某角色的中文名（该 NPC 的目标，玩家与导演讨论时替 NPC 设立，如「王蓉想让主角答应下周跟她一起去接货」）。2026-09-13 前这里用魔法串 `player` / `npc_xxx`，主角入人物表后统一为"空串 = 主角、否则 = 角色中文名"（主角也是人物表里的一员，见 TDD §2.1.2）。NPC 目标由该 NPC 在戏里主动推进：在场 → 自然提及（试探/欲言又止）；不在场 → 主动来找玩家（登门/路遇/托人带话）；**只对挂在未完成大目标下的子目标这么做**（防止支线无限拉人登门）。
- **引导（编剧职责，非引擎机制）**：剧情目标块置于资料区尾部（事件日志之前，位置 2026-09-12 用户明确不动）。渲染成**两级树**：大目标带「子目标 x/y 已完成」进度，子目标缩进，未挂靠支线单列一节。**引导纪律分层**——大目标是方向盘（每回至少推进主线一步，且优先沿它下面的小目标走）；小目标择机落地（只在与当前场景/在场者相关时推，不必每回都碰）；一次只推进一小步，禁止一轮内生硬给出全部结果；目标之外的自由展开不受限制。
- **完成判定（审计）**：采纳时审计按已采纳正文判定目标是否实现——小目标 = 当事达成；大目标 = 关键真相/冲突已解决。只推进未达成的不填（推进由编剧纪律负责，审计只判终点）。**推进 ≠ 完成**：目标 NPC 提及/推进目标（王蓉提起接货）只是推进，只有正文里目标所述之事真正发生（玩家答应了）才判完成。**大目标是章节**：其下「子目标 x/y 已完成」只作参考证据、不是判据——正文给出明确的关键了结（即使子目标没走完，如玩家绕道达成）即可判完成；只是把子目标推了推、关键冲突没解决就不判。判定后目标置 done，记 done_at。
- **级联闭合（数据卫生，不判剧情）**：大目标置 done / abandoned 时，其下仍 active 的子目标一并置 abandoned（父结束、支线失去依托；留着会被编剧继续当"下一步"推）。不落事件、不进正文。
- **可见性**：玩家侧栏"剧情目标"两级树（大目标带 x/y 章节进度、子目标缩进、已完成子目标划线，未挂靠支线单列）。导演窗口的目标列表带 id（2026-09-12 前一律不吐 id，导致 set_goal 的"废弃"与"挂父"实际填不出来）；戏外动作确认卡片提供"挂到主线"下拉，这是建立父子关系的唯一 UI 入口。
- **玩家是作者**：目标由玩家设立与废弃，引擎不自动生成小目标、不自动提取承诺；"答应过什么"类即时问答走导演窗口答疑（查事件流）。
- **钩子台账已废弃（2026-09-07 拍板）**：原"审计自动提取承诺/未了事"不行——玩家看不到、不主动产生剧情，实际未发挥作用。其"内容包预置主线种子"的扩展方向一并废止，主线即玩家主动设立的大目标。
