> **定位**：AI World 引擎的运行时机制需求清单，经"实况模拟"讨论法收集（县城/高中暑假推演），是 GDD（策划）／TDD（技术）并列的第三份输入文档。

## 〇、数据契约：NPC 档案 / 事件条目 / 世界设定 / 元配置

> 本章是数据底座，是所有机制共同引用的内容来源：NPC 档案（①②③ 三分类）、事件条目默认公开与 known_by 私密名单、秘密的存放规则（幕后注 / 注入记忆）、世界设定两级（概要常驻 / 世界书按需）、元配置·叙述预设。

### ① 人物卡 · 初始状态　（作者离线预制 · 开局写死 · 只读）

- **内容 = 外貌 / 人格**。人格合一格：性格 + 特点 + 说话风格 + 前史 + **身份定位**（职业/辈分/社会身份等定位资料并入此格，2026-09-05 拍板：不设独立身份字段）——全部为 LLM 语义消费内容，供台词书写与文风核对时整体取用（性格/特点回答"他是怎样的人"；说话风格 = 语气/用词/口癖；**前史 = 游戏开始前已存在的过去**，童年/来历/前缘/旧伤，作者开局可写；补充童年经历类资料一律落此格，② 是运行时事件流的累积，开局前的事属于 ①）。UI 层可在格内分段展示（性格 / 前史），存储保持一格。**主角与 NPC 同构**：玩家资料亦为 名字/外貌/人格 + 幕后注/自知隐秘（无 has_actor），背景字段已删（详情并入人格）。两字段语义：
- **自知隐秘**（玩家个人秘密）：只有玩家自己知道（如"夜里是假面骑士"）——任何 NPC 说出或提及即泄漏（同学不会说"你就是假面骑士"）；玩家可选择何时亮牌，亮牌 = 一场揭露新戏。
- **幕后注**（特殊背景）：连玩家也不知道的底牌（如"受神之加护，但赐予者名雅典娜"）——只有编剧运行时可读，用于埋伏笔/让神迹自然发生，正文揭示即泄漏。
- **秘密 = 未叙述真相**（规则见本节「秘密 · 叙述即公开」），作者下笔时按知情面分两格：
  - **幕后注**（作者底牌）：**无人知道**的真相（含 NPC 自己也不自知的命运底牌与涉密前史）——可选私区，仅编剧运行时可读，永不进任何切片（含 NPC 本人）与玩家视角。
  - **personal_secrets**（NPC 自知隐秘）：该 NPC **自己知道**、不为外人道的心结 / 往事 / 把柄（"他爸欠了赌债，他最不愿提"）——进该 NPC 本人的 Actor 深抉择切片（"你心里的事"），**不**进玩家、其他 NPC 与任何引用域；编剧全知侧同见（标注"XX 自知"）。真相首次被叙述（玩家撞破 / 查出 / 他人泄露）时落库为新事件，此后按叙述情境入引用域。
- **只读 + 增补路径**：① 的内容在开局后保持固定，② 经历（追加）与 ③ 属性（覆盖）随剧情演化；作者补设定或角色升格需要增厚 ① 时走**补卡事务**——玩家在导演窗口口述期望 → 导演拟稿并与事件流一致性核对（对照已发生经历与他人前史）→ 玩家确认 → 落卡。字段增补一律经此路径完成。
- **引擎配置字段同落此卡**：
  - **has_actor 档位初值**：作者在内容包预标重要 NPC，即兴角色转正时决定初值。档位判定读存档世界实例的人物卡；玩家要调整时直接编辑存档世界实例的人物卡（不经导演窗口；2026-09-05：原"正常日程"字段已移除——NPC 习惯画像不再做引擎级基线，位置推断只用"最后事实 + 身份隐含大框"）。

### ② 经历 · 随回合累积　（追加日志 · 时间线可回溯）

- **内容 = 事迹与记忆（规则化拼接条目，规则见三章）+ 当前状态缓存**（最近结算摘要：此刻位置 / 受伤 / 临时覆写），供装配、面板直取。
- **位置真相在事件条目**：每个事件条目自带位置与时间戳。"此刻在哪" = 该实体最近一条相关事件（记 位置 · 时间 · 来源=目击/事件/覆写）。位置由事件推导，旧事件随世界钟过期后降级为推断素材（M18 同规则）。情绪 = 引擎从该实体最近事件流得出的推断值，随事件刷新、按需现算。
- **账本状态字段同落此层**：M16 注入登记留痕（纪律见二章 M16）。

### ③ 抽象属性 · 可变数值　（内容包声明 · 引擎每回合结算覆盖）

> **暂缓**：本分类与 M5 关系结算为二期设计，v1 不在引擎中结算； schema 可预留，但 v1 不写入、不读取关系轴。

- 内容包按题材声明轴：`{id / 标签 / 范围 / 初值 / 可见性 / 归属实体}`——冒险世界 = 力量、敏捷；恋爱世界 = 好感、信任。挂玩家或 NPC。
- **关系轴**（可选标记，带目标实体，如"好感 玩家→朱明"）：标"记因"的关系轴每次数值变化自动在 ② 落一条账（谁 · 因何 · 影响谁 · ±多少），关系变化的因果全程可回溯。
- **可见性**：玩家面板只显示 `visible=true` 的轴；`visible=false` 的轴在玩家面板之外照常参与引擎结算。

### NPC 生命周期　（实体级状态位：active / retired）

- **退场 = 状态变化，实体数据全保留**：死亡 / 永久离开的终态事件由世界审计例行扫描发现 → 置 `retired`。复活 / 诈尸 = 剧情事件翻转状态，数据层随事件翻转、导演排戏。
- **retired 后的处理**：

| 项 | 处理 | 归属 |
|---|---|---|
| 主动调度与推断 | 该角色停止参与引擎的主动调度与位置推断 | 规则 |
| 数据保留 | 人物卡（含幕后注）/ 经历 / 关系轴 / 记忆条目一律保留在账本 | 自动 |
| 位置 | 死亡后最近相关事件即终点 | 规则直落 |
| 剧情目标（M14） | 未完成目标保留在账本；是否继续推进由玩家定夺（废弃=导演窗口 status: abandoned） | 玩家 |
| has_actor | 档位保留；无戏份时深抉择零触发、Actor 零调用 | 自动 |
| 关系轴 | 冻结，停止结算 | 规则 |
| 未叙述真相的揭晓 | 死者幕后注 / 注入记忆维持原样；是否揭晓（遗言 / 遗物 / 他人目击）由导演编排为戏，叙述即落新事件 | 导演编排 |

- **推论**：退场者的条目照常被他人引用、回忆——事件流作为真相层，记忆条目的可引用性与本人状态无关。
- **升格 = 角色重要性上升时 has_actor 档位单向升档**（信号与判定规则见三章「升格通道」）；升格触发补卡事务（①）。建档转正（即兴 → 有卡）与派活升格（代笔 → Actor）是两条单向升档的通道。

### 秘密 · 叙述即公开（事件条目默认公开 · known_by 私密名单）

**结算范围 = 玩家可感知**：结算只发生在玩家在场的戏与玩家声明跳时后的简报（M20 / M8 时段戏）。因此**每条叙述性事件落库时玩家都在场或已见报**——事件流里没有"玩家不知道"的情节条目。不被叙述成戏的真相不进事件流；导演的静默调度（M18 覆写）落统一事件，只描述位置、不承载情节，玩家在戏中见证其效果。

- **公开 = 默认态**：叙述性事件落库**默认不挂 known_by**，即为**公开条目**——玩家与任何 NPC 皆可引用，地位等同公共知识（校门口打架传遍全镇由此而来）。公开 ≠ 必被提及：引用与否由叙述层相关性决定（说书人选材 / 导演排戏 / 质检拦突兀）。
- **`known_by`（私密名单 · 可选字段）**：事件被判定为私密时才写，值 = **知情者闭集**——当场在场者集合（M18 查询：最近位置 = 该场景的实体；注入记忆条目 = 被注入者，见 M16；导演静默覆写是位置记录、不载知情语义）。职能 = **记忆切片边界**——NPC 只引用公开条目与 `known_by` 含自己的私密条目，名单外的 NPC 查不到这条。玩家见证每条叙述性事件：公开条目人人可引，私密条目以在场者身份落在 known_by 内。事件正文是已发生史实、落库原样保留；known_by 是访问控制状态，可按本节「访问状态改判」变更——正文与访问权分层。
- **挂载判定 = 叙述情境**：落库时看这场戏**有没有被场外自然得知的通道**——公开情境（校门口打架、围观可见）→ 不挂，条目公开；私下情境（密室密谈、四下无人、隐蔽动作）→ 挂当场在场者闭集。导演排戏时判定、落库即定初值，不为"要不要保密"增设任何字段或场景属性；初值判错可经玩家纠错改判（见下「访问状态改判」）。
- **访问状态改判（正文史实不可变 · 访问权可修正）**：known_by 是**访问控制状态**而非一次写死的记录——正文（当时发生了什么）一经落库永不修改；"谁能引用"这一访问状态允许**修正**。改判只重设访问状态：不产正文事件、不改任何旧条目正文，玩家在导演窗口提出、导演执行后落账。改判粒度 = **单条事件**，逐条点名、逐条执行。
  - **改判私密 · 玩家纠错（公开 → 私密）**：玩家回看事件日志，认为某事件当时实为私下情境（密室对话 / 四下无人）却被落成公开 → 要求导演改判 → 重设 known_by，**名单由导演/玩家直接给定落账**，引擎不做检索起草。改判是**补救行为**：事件公开期间可能在剧情上传给了在场者之外的任何人乃至无数人，逻辑上不可能全部收回；玩家选择改判，即**接受"已传开者收不回"的逻辑代价**（为更大的叙事理由压过它）——名单内 NPC 保留知情，名单外 NPC 自此查不到这条，已传出的部分不做追溯、不设传开闸。
  - **改判公开 · 玩家纠错（私密 → 公开）**：玩家认为某私密条目系导演误挂名单（实为公开可闻情境）→ 导演清空名单恢复公开。
- **世界事实公开化（官宣 / 恋情公开）不靠改判，靠叙述**：两人决定公开关系 → 导演排一场公开戏落新事件（当众宣布 / 牵手同游，公开情境）→ 全镇自此可引"他们在一起"。**历史私密条目保持私密**——官宣开的是"关系状态"这条新事实的引用权，不是翻旧账；当年私密约会细节仍只有当事人在场者可知（真实世界同理：官宣后别人知道你们在一起，仍不知道你们约会时的私密细节）。玩家想让某条具体历史私密条目一并公开，逐条点名走上方「改判公开 · 玩家纠错」。
- **秘密 = 未叙述的真相**：事件流对玩家无盲区，"秘密"因而不是事件流上的隐藏条目，而是**尚未被叙述成戏的事实**，三种形态：① 幕后注（作者底牌 / 涉密前史，见 ①）；② NPC 档案注入记忆（导演后台补料，见 M16）；③ 导演排戏意图。三者都进不了玩家视角与任何 NPC 切片，导演运行时可读。
- **揭晓 = 叙述一场戏**：玩家撞破 / 查出 / 他人告发 / NPC 主动坦白 → 导演排一场戏 → 真相首次成为正文 → 落一条**新事件**，按叙述情境入引用域（私下坦白 = 私密条目，known_by = 当场在场者；当众揭发 = 公开条目）。旧条目原样——**知情扩散只经新戏落账**，正文事实不回头改写；已成文条目的访问修正（改判私密 / 改判公开）与关系公开化（官宣）走上方「访问状态改判」「世界事实公开化」两条通道，与正文改写两回事。被转告的 NPC 其知识来自转述 / 共历的新戏条目。
- **知情差异照常模拟**：已叙述的**私密条目**其知情差集 = known_by 查询；公开条目无差集（人人可引）。玩家"看见却装不知"→ 对方按不知演，亮牌 = 一场对质新戏。玩家对见证过的事守口与否是玩家自由，泄密的叙事后果由导演排戏处理——世界不会因"玩家知道"自动得知。
- **知情约束 = 单一总纲「角色不是你」（2026-09-09 收敛，原泄密条/知情常识条/即兴角色条三合一）**：编剧案头资料（事件日志、幕后注、世界书）角色本人并不知道；角色开口前须核对话词是否在其自身已知范围内——亲历（事件日志在场者标注）、来历（人物卡）、被告知（剧情内）。派生三特例：①**泄密**——幕后注/私密条目绝不能从不该知道的人嘴里说出（知情者坦白除外，落新事件）；②公开条目「可引用」是上限不是行为——异地角色的外地旧事默认不知（轰动大事可作风闻，鸡毛小事传不出远门）；③**即兴角色**（无卡）只知眼前可感知区，不引用日志旧事。判断由编剧成文时执行（金科玉律承载，判断依据 = 事件日志发生地/在场者/时间标注——**数据做重活，规则讲原理**，不 enumerate 特例）；Actor 路径天然免疫（切片只有亲历与名单内事件）；即兴角色另有结构免疫（无卡无切片无工作单块）。不为公开事件建传播名单、不设入镇时间等状态字段（收刀判据）。
- **NPC 握有的牌**（"朱明握有王蓉的把柄"）只存在于注入记忆 / 幕后注，是待叙述的真相；何时、以何种方式被玩家发现由导演按戏编排，被发现即落新事件。
- **推论——可引用全集** = 世界概要 ∪ 公开事件条目 ∪ {私密事件条目 \| known_by ∋ 引用者} ∪ {世界书条目 \| 本场导演点名展开}。世界概要常驻每份工作单；公开事件条目与点名展开的世界书条目按装配相关性取用（装配细则见下小节与三章切片）；私密条目按名单。幕后注不进入任何切片，只经"叙述"转为事件后进入引用域；注入记忆以私密条目（known_by = 被注入者）直接进入被注入者的引用域。

### 世界设定 · 概要常驻 / 世界书按需

作者直写的内容包世界设定天然公开、人人可引——与公开事件条目并列为两个公开引用来源。它分**两级**，装配策略不同：

- **世界概要（world_summary）**：作者用几句话框定时代 / 地点 / 基调，并把**硬规则**写死在概要里（"与现实世界无异，没有超自然力量"）。装配时**常驻每份工作单的 system 块、永不裁剪**——LLM 以概要打底、凭自身知识补足细节。概要管"绝不可违背"，人人可引。
- **世界书（lorebook）**：详细设定条目数组，每条 = `{ id · 关键词 · 正文 }`（v2：无摘要层）。天然公开但**默认缺席任何切片**——触发 = 零 LLM 关键词匹配：`save.active_lore_ids` 由引擎两处维护（预结算阶段玩家输入命中追加 / 采纳阶段按已采纳正文清空重建，上轮事实优先、上限 5 条去重）；工作单只读该列表，按 id 取条目**正文全文**拼入编剧/导演工作单。世界书不设 known_by（无访问控制的隐藏设定属幕后注 / 秘密范畴，不是世界书）。
- **铁律一：硬规则只进概要、不进世界书**——世界书条目无人点名即不受约束，凡"绝不可违背"必须常驻，否则不查书的工人会写出违背世界观的戏。
- **铁律二：世界书运行时不追加**——作者只读静态资产；即兴补出的世界细节（"镇上其实有家旧戏院"）走叙述落事件流，不回写世界书。

### 元配置 · 全局叙述预设

预设是**全局通用配置**，不随世界资产包走；存于 `data/presets.json`。界面只提供两个大框：

| 成员 | 内容 | 消费方 |
|---|---|---|
| **导演准则** | 自然语言排戏规则，例如“不要主动揭穿秘密”“优先让 NPC 主动制造冲突” | 导演判定 |
| **说书人预设** | 自然语言正文写法，例如文风、描写方式、禁用词等 | 说书人成文 + 质检核对 |

- 玩家在设置面板里编辑这两个大框，保存后全局生效。
- 说书人初稿按说书人预设直接成稿；质检按同一块内容做一致性核对。
- 导演判定按导演准则排戏。
- 原有的 `style / description_style / banned_words / pace` 仍作为内部兼容字段保留，界面不再单独展示。

> **衔接**：各角色读档案的切片规则见三章「发声与视图隔离」；各机制的数据落点在本章——M19/M18 移动与在场产生位置推导依据，M5（二期预留）结算写关系轴并在②自动落账，M16 注入留痕存②，M14 从事件流与导演窗口取目标素材，M1/M18 以①最后事实与②事件推导做推断基线。

## 一、时钟与空间（M20 / M17 / M18 / M1 / M19）

### M20 · 时间推进：语义驱动

**一句话**：时钟由语义驱动——推进只发生在三类输入上；对话回合是时钟冻结态。

- **推进来源三层**（规则直落，无需专门 agent）：① 玩家声明时刻（"等到中午""第二天"）→ 规则认字直接推进；② 干实事未提时间 → 按默认档耗时（修电脑≈20min，移动按 M19 耗时）；③ AI 正文写了时间流逝（"天黑了"）→ 该次输出顺带同步推钟。
- **叙事时间与世界时钟分轨**：天色 / 气氛描写可自由流淌；正文要真正推进时间必须按 ③ 同步推钟，正文与时钟保持一致。
- **离线状态**：时钟只在有输入回合时推进；存档离线期间世界时间停留在最后推进时刻，重开时从该刻续走。
- **世界钟起点 = 内容包资产**：`world.json.start_time`（ISO 时间，可选）声明该世界的开局时刻；新建存档与重置存档都回到此起点（缺省回退引擎默认 2026-07-14T08:00:00）。作者改一个字段即可让世界从任意时刻开局，开场白时间戳随之对齐。

### M17 · 场景注册表与双轨生成

**一句话**：地点 = 预置为主、现场补全，补全即注册、可复用。

- **预置（骨架）**：内容包 world.json 写死常驻地点。场景节点属性 = `名字 · 标签 · 可感知区 · 开放时段 · 邻接点`。
- **现场补建（转正）**：玩家走进包外地点（"街角新开的奶茶店"）→ 引擎生成节点挂到邻接图并注册，之后可复用、可被 NPC 提及。
- **一次性布景**：只去一次的剧情地点（密室/郊外旧楼）按剧情使用，用完即从可导航集退场，事件流仍可回溯引用。
- **推导锚点**：NPC 位置推断（M1）、导演取景编排全部锚定注册地点与可感知区。
- **转正判定：来源定初态 + 引用信号驱动**。
  - **初态由来源决定**：玩家声明的地点（"走进街角那家奶茶店"）一律当场注册——玩家宣示世界事实；导演排戏捏的舞台默认临时；说书人写景顺笔的地点（"巷口有家旧书店"）视为装饰性文字。
  - **转正信号（引擎被动核对）**：① **玩家回访 / 指代**（"回刚才那家奶茶店"）——最强信号，指代消解依赖该地点已注册；② **剧情目标指向 M14**（该地点是某目标的节点）——未来引用概率高；③ **导演/NPC 复用**（下一场戏再用此舞台 / NPC 拿它当惯常地）。任一信号出现即当场补注册（加节点 + 挂邻接边 + 补标签）。
  - **成员资格**：注册地点才进入可导航地图与 M1 位置推断候选集；未注册地点的事件引用仍在事件流内可回溯。
  - **导演可预注册**：排戏时预知舞台会复用（如安排成某 NPC 秘密据点）→ 显式命令立即注册。

### M18 · 位置与在场者

> 注：位置/在场没有独立位置表，均由统一事件流事件（`location + participants`）推导。

**一句话**：谁此刻在哪、谁在当前场景，由事件流事件推导直接给出。

- **查询规则**："X 此刻在哪" = X 最近一条带地点且包含 X 的事件；"谁在当前场景" = 最近事件中地点为该场景的实体集合。
- **场景 = 该地点的在场实体集合 + 可感知区**（M17 节点）。世界惰性渲染：场景在玩家到达或询问时才生成描述。
- **位置 = 事件推导**：事件记录携带 `location` 与 `participants`；某实体在某事件中出现，即表示“那个时刻他在那”。旧事件随世界钟自然成为历史锚点。
- **过期降级为推断素材**：历史事件成为锚点（"三天前在网吧"），查询回退到"上次事件 + 时间差 + 人格隐含大框"上推断。
- **空档位置查询 · 三件套**：① 最后一条相关事件；② 人格隐含大框先验（"开店"类日常场所，来自人格格的身份定位资料）；③ 时间差。引擎合成"此刻他在哪才合理"的候选域 → 导演在域内做叙事落点（网吧 = 通宵惯性；家 = 宿醉补觉；被禁足 = 覆写 + 现编解释，见 M2 故事道），玩家进门那刻的在场结算对导演落点执行——导演拍板本身落一条新事件。
- **覆写 = 统一事件**：导演/玩家覆写 = 写一条统一事件（如“朱明在网吧。”）；该事件优先于旧事件与推断。
- **离场去向**：NPC 离场后停在最后事件；有人进场/询问时若该事件已过时，按空档三件套重推。
- **未来时刻位置**：位置的写入时机 = 结算 / 覆写当场。导演排"某日他在某地"的戏份时当场落一条事件或事后排一场戏，账本随结算成长。

### M1 · NPC 动态位置推断

**一句话**：NPC 此刻在哪 = 按「最后事实 × 时间差 × 人格隐含大框 × 地点标签」推导出的候选结论，供目标解析与导演排戏取用。

- **触发**：玩家说"去找朱明"但没说去哪；导演排戏需判断某 NPC 此刻可能在何处。
- **核心设计**：① 事件流事件（M18）提供最后位置与覆写 ② 场景注册表（M17）提供地点标签与开放时段 ③ 时间差。2026-09-05：正常日程字段已移除，习惯先验不再引擎级建模——候选域由最后事实 + 人格隐含大框（"开店"类日常场所，资料在人格格）合成，他是否真在那由导演按叙事拍板（M18 空档三件套）。

### M19 · 移动解析与场景切换裁决

**一句话**：玩家去哪由意图解析决定（玩家叙述优先），引擎执行裁决链。

- **目的地解析四种**：① 地点直命中（"去网吧"）；② 由人推位置（"去找朱明"→ M1）；③ 指代回溯玩家记忆（"昨天那家店"）；④ 未建档地点 = 接受声明 + 现场注册（M17）。另"随便走走"进入**漫游态**（沿邻接边慢移，导演可排偶遇/沿途发现）。
- **NL 判断边界**：自然语言只在意图解析一处被判断；其后可达 / 耗时 / 在场结算全走规则 + 账本。
- **裁决链**：查可达（邻接图）→ 结算耗时推进时钟 Δt →（可选）沿途编排 → 到达 → 在场者查询（M18）→ 场景描述（模板底稿优先，见下）→ 上下文重装配（只含可感知区）。
- **移动粒度**：A→B 场景直达、一步结算耗时。
- **场景描述 · 模板优先**：常规到达 = 引擎按 M17 场景属性（标签 / 可感知区 / 开放时段）拼静态底稿，尽量零 LLM；首次到达新场景 / 剧情舞台 / 需特殊氛围的地点，导演升级派说书人按叙述预设专门成文。
- **混合句 · 导演一把抓**：一条消息含多个意图（"去网吧找朱明，问他打架的事"）→ 引擎先预结算规则段（可达 / 耗时 / 在场者查询 / 位置推断，M1 / M18 照常执行）作为导演输入，导演把移动与对话作为**同一场戏一次判定**——衔接顺序（先到后聊）由导演在剧本指令内编排，正文一次成稿。

## 二、信息边界：玩家声明、记忆与注入（M2 / M16；秘密与 known_by 规则在〇章）

### M2 · 玩家叙述优先 / 世界状态覆写

**一句话**：玩家声明的世界状态即事实、立即落库；状态的"理由"在出口时现编并实体化。

- **触发**：玩家说"朱明在家睡觉没起床"，与 M1 推断（网吧）冲突。
- **事实道（实时）**：声明直接落一条事件流事实（位置/世界状态，写操作），调度、他人查询全以此为准。
- **故事道（理由惰性）**：账本只存事实；待该 NPC 被撞见且玩家疑惑/追问才现编解释（"前几天刷夜被抓，我妈不让出门"），说出口即落库为事件（私下情境 → 私密条目 known_by=[该NPC, 玩家]；注入纪律见 M16）。
- **最小世界侵入**：解释尽量复用既有实体与事件链；需要引入第三方（"他爸"）时同步建档入流，先浅后深、追问才往深编。
- **位置衔接**：覆写 = 落一条统一事件（如“朱明在网吧。”），该事件优先于旧事件/推断（见 M18）；后续新事件自然更新。
- **冲突处理**：玩家声明的世界状态即事实，无论与既有事件是否一致都直接落账——一致与否由玩家自决（玩家是作者，引擎不做矛盾仲裁）。

### M16 · NPC 记忆注入

**一句话**：人设永远写不全，剧情需要补背景时走两条纪律分明的路。

- **作者注入**：作者写内容包 / 编辑 NPC 卡 → 直接改数据，无运行时风险（本质是写卡）。
- **运行时注入**：LLM 剧情中补全 → 登记落库进 NPC 档案。三条纪律：① 注入内容与已叙述事件保持一致，确需修正时登记为修正并留痕；② 注入即登记，之后引用系统对得上账；③ 涉密补全 = 登记为被注入者的记忆条目（私密条目，known_by = 被注入者）——玩家与无关者的切片里没有这条；真相待玩家撞破 / 查出，叙述即落新事件。
- **本质**：未叙述的真相可以后补进档案；出口（被说起）即固化为正式事件——补全内容与已叙述事件保持一致（纪律①）。

## 三、角色纪律：导演方案（叙述架构）

> 源头问题：任何"全知大脑"代笔角色都可能说出不该知道的话。本组纪律定两件事：**决策可多脑**（导演拿主意、Actor 演深抉择）、**文字唯一 + 必经质检**（说书人动笔、质检员把关）。

### 角色清单与账本纪律

架构总纲：**记忆全部收进账本（引擎数据库），Agent 全是无状态工人**——开工前引擎现配"本轮工作单"（小且固定），干完写回、转身即忘。状态是输入（每轮新鲜装配置顶）而非要求维持的输出；存储永远是账本的活，Agent 只回写"变了什么"。

| 角色 | 职责 | 调用 |
|---|---|---|
| **导演**（决策中枢） | 判断本回合"戏的走向"：玩家输入已成文 → 核对节奏后采纳；不完整 → 判定缺什么、从账本取料补全（人设×情境决定 NPC 反应方向）；空泛 → 按**玩家所设**节奏档自由编排。产出分层剧本指令，正文由说书人成文 | 每回合必经 |
| **NPC Actor** | `has_actor` NPC 遇深抉择（内心判断 / 涉密反应 / 是否信任）时以自身视图隔离决策 | 触发 +1 |
| **说书人** | 把剧本指令写成正文——唯一正文笔 | 需成文时 0~1 |
| **质检员** | 必经前置文字关：文风把关（按叙述预设核对/润色）+ 泄漏比对（见本章末条） | 每回合必经 |
| **世界审计** | 采纳时提交后结算：时间推进同步 / 关系结算（二期）/ 目标完成判定 / 生命周期扫描 | 采纳时同步 |

- **回合调用账**：导演(1) →〔说书人(0~1)〕→ 质检(1) 串行必经；NPC Actor 触发 +1；世界审计在采纳时随提交后结算完成。**感知延迟 ≈ 2~3 跳**——质检必经是玩家拍板（质量优先于延迟），降本靠：质检用辅助模型 + 局部改写（只动需改句，整段无恙原样透传）。
- **回合流水线三保障**：状态外置（模型靠账本供料）、工作单每轮现拼（小且固定）、写回账本走 schema 校验——多 Agent 的价值 = 视图隔离。
- **记忆条目 = 引擎规则化拼接**：把已记账的结构化字段（时间 / 地点 / 行为类型 / 在场者）按固定模板拼装成条目（时间+地点+谁干了什么+在场者），LLM 的唯一参与 = 补一句**定性附注**（"她语气不对劲"）。条目原料只取已记账字段——每轮概貌稳定、成本确定。

**导演窗口（OOC 戏外工作台）**：仅玩家主动开启，导演纯被动。窗口内所有话都是**戏外话**——玩家说了 ≠ 主角在戏里说，导演的话 ≠ 正文。窗口产出三态：给建议 / 答疑问 / 改账本：

1. **求建议**（玩家没创意）：导演扫 M14 剧情目标 + **当前叙事张力**（关系状态、节奏档、未推进的目标）现排 2~3 个建议——既收尾型（"该去赴约了"）也**推动型**（"上去抱住她"）。
2. **答疑**（玩家忘事）：如"王蓉喜欢什么？我答应过她什么？"→ 只读账本简略回答（NPC 档案 / 事件流 / M14 台账）。
3. **剧情讨论**（双向磋商）：商量下一步怎么更合理 / 更有张力 / 更合玩家偏好 → 聊定后导演给一段**简略输入建议**，玩家复制进正文输入框执行；玩家表达的叙述偏好（节奏 / 文风 / 描写方式）→ 到〇章「元配置·叙述预设」设置里调整，导演只按玩家最终设置执行。
4. **幕后事务**（账本操作）：
   - **静默覆写 / 调遣**："朱明明天去夏令营"→ 导演直接落一条统一事件（source=director）+ 给该时段排一段戏（时间推进随该段戏按玩家声明跳时结算，见 M20），正文以"已发生"为基演出。位置随导演排戏当场落账，随结算成长。
   - **角色档位调整**：不在导演窗口操作——配 / 取消 Actor 由玩家直接编辑存档世界实例的人物卡（`has_actor` 字段）；人物卡厚度不足时先走补卡事务。
   - **事件访问改判**：玩家回看事件日志，认为某事件初判公开/私密有误 → 要求导演按〇章「访问状态改判」处理（改判私密 = 名单由导演直接给定落账，不做检索起草——改判即玩家接受"已传开者收不回"的逻辑代价；改判公开 = 清空名单恢复公开；官宣类公开化走排公开新戏承载）→ 确认后只改访问状态、正文不动。
- **扶手规则**：一切建议在玩家**采纳**（复制 / 确认）后执行。观察 / 打量等描写请求在**正文窗**输入，走正常正文流水线（导演取 人设×状态×情境 → 说书人成文 → 质检）。

**NPC 决策二分归属**：轮到 NPC 反应 / 决策时——**有 `has_actor` → 决策需求派发给其 Actor 自主决定；无 → 导演代笔**（无专属 Agent 的人物通常重要性不足，泄漏面小，由质检兜底）。

- `has_actor` 是**运行时档位**，初值落卡（〇①）：作者内容包预标重要 NPC；即兴角色转正时决定（深聊对象默认配）。Actor 是储备——日常浅反应导演照旧代笔，深抉择才派活。
- **角色档位（2026-09-05 简化）**：配 Actor 与否由玩家直接编辑存档世界实例的人物卡（`has_actor` 字段）管理，不经导演窗口。玩家可随时配 / 取消；人物卡厚度不足时先走补卡事务；功能性发声（招呼 / 跑腿 / 敷衍）属模板层走话术模板。原"点名强制档"（浅反应也派）已取消——浅反应一律编剧代笔。
- **升格通道（单向升档）**：角色重要性上升（路人的王蓉开始恋爱 → 深抉择变多）时，规则给信号（关系轴升温〔二期信号〕 / 连续深聊 / M14 目标挂账）→ 导演在幕后事务判定升格（改一个标记位，正文随之演她越来越像自己）。无戏份 = 深抉择零触发 = Actor 零调用零成本；永久退场走〇章 `retired` 状态位。
- **升格触发补卡事务**：升格后人物卡厚度不足（性格可细化 / 说话风格不够 / 前史空白）→ 走 〇章① 补卡事务：玩家口述 → 导演拟稿 + 事件流一致性核对 → 确认落卡。
- **浅反应导演编排、深抉择派 NPC 自己演**：脸红低头这类表象反应导演直接排；"是否背叛你"这类内心深水区须派 Actor。
- **导演交付物分层**：剧本指令分**可见层**（脸红 / 低头——正文只写这层）与**动机层**（暗恋——只进账本与后续剧情参考）。导演读幕后注与未叙述真相是安全的——导演产出物只到剧本指令层，正文一律由说书人成文；闸口在分层交付。

### 发声与视图隔离

按"有无 has_actor × 是否深抉择"分执行档：

- **V0 功能性发声**（招呼 / 跑腿 / 敷衍）：话术模板 / 规则，尽量零 LLM。
- **代笔路径**（无 has_actor，或 has_actor 的浅反应）：导演排、说书人写。
- **Actor 路径**（has_actor × 深抉择 × 触及受限区）：派发 Actor，上下文**物理隔离**——Actor 输入只含 persona、自己的记忆切片、引用域内的可引知识（公开条目 + known_by 含自己的私密条目）+ 本场 directive 点名展开的世界书条目。信息密度是天然防护——无知识性台词的角色永远安全。

### 即兴角色两机制

AI 可能现场捏角色（乞丐），其档案 / 视图 / 引用权在到场那一刻全部空白——无切片者，公开条目与私密条目都不装配给它。对策：**知识只能经给料边界进入角色的嘴**。

1. **给料即资格 · 可感知原则**：有切片者（预注册 NPC / 玩家）自带切片知识开口；无切片者（即兴角色）台词只引用 scene 可感知区里的内容（可感知描述、当前可见之物）。scene 只放可感知描述——处理现场干不干净成为有 gameplay 后果的行为。
2. **转正仪式**：玩家深聊即兴角色 → 现场建档（persona + 初始引用权：登场前的私密见闻"他见过满身是血的你"立为 known_by 含该角色的私密条目）→ 正式进视图系统；顺带决定 has_actor。

### 质检员 · 必经前置文字关

说书人初稿（或导演直接采纳的玩家原文）**一律过质检才送达玩家**：文字修饰 / 文风一致性 + 泄漏比对一次完成。送达即进入**候选区**——质检管"够格呈现"，玩家采纳那一刻才落账成史实（见下「玩家采纳 · 回合事务」）。

- **输入两区**：正文初稿（可改）+ 受限知识参照区（只读比对——参照区内容与正文成品分轨，成品只取初稿与改写）。
- **泄漏命中 → 脱敏改写**（模糊化表述）。
- **矛盾不设引擎仲裁（2026-09-05 拍板）**：剧情走向与既定设定的一致性是**玩家的判断**——看得出矛盾玩家自己处理（重掷 / 放弃 / 导演窗口覆写），看不出说明其不重要。质检不设矛盾分级、不挂队列、不提示。文风依据 = 〇章叙述预设：编剧初稿按预设·文风与描写方式直接写；质检按同一预设做文风一致性核对 + 禁用词硬拦（命中即改稿）。预设是每轮装配的输入，玩家覆盖对**后续轮**生效。
- **文风依据 = 〇章叙述预设**：说书人初稿按预设·文风与描写方式直接写；质检按同一预设做文风一致性核对 + 禁用词硬拦（命中即改稿）。预设是每轮装配的输入，玩家覆盖对**后续轮**生效。
- **泄漏 = 剧情错误**（OOC 子类）——每个 LLM 都知道它会被查。

### 玩家采纳 · 回合事务（落账闸门）

**一句话**：一回合 = 一个事务。正文过质检送达玩家后仍在**候选区**，玩家从候选版本中选一份采纳（显式，或只有一份时的下一次输入自动采纳）那一刻才整体原子落账——质检管"够格呈现"，玩家采纳管"算已发生"。

- **候选区**：送达 → 采纳之间，该回合的**多个候选版本**（初稿 + 各次重掷结果）与**全部账本副作用**（时钟推进 / 位置变化事件 / ② 经历 / known_by 初值）一并暂存，账本零写入。重掷/抽卡只新增候选版本，不删除旧版本。
- **下一次输入 = 默认采纳（仅单候选时）**：若当前只有一份候选，玩家不点“采纳”直接提交下一条指令时，引擎先把该候选整体原子提交，再进入新回合；不打断玩家连续操作。若当前有多份候选，玩家必须先选择采纳哪一份，引擎不自动替玩家选。
- **采纳 = 原子提交**：从候选版本中选中的正文成事件条目，副作用一次生效，回合闭环；提交成功后清理该回合其余候选版本。
- **放弃 = 整体回滚**：明确放弃当前回合时，该回合全部候选版本一并清理，账本无痕——同一回合不会留下"两版都发生过"的时间线分叉。
- **重掷三档**（玩家对已送达候选不满意时，每档生成一份新的候选版本，旧版本继续保留供比较）：
  - **换说法**：同一份剧本指令，只重跑说书人换写法——廉价，适合"写得不够味"。
  - **换走向**：导演重排整场戏、决策重判——全链重跑，适合"这反应不对 / 戏不该这么走"。
  - **定向重掷**：玩家口述不满处（"别让他这么快坦白"），导演按意见改——一次命中；导演窗口可对话，定向优先于盲抽。
- **采纳后 = 史实**：此后反悔走导演窗口（访问状态改判 / 覆写），与候选区重掷分轨——导演窗口幕后事务同此闸门：玩家提出、确认后落账。
- **叙述的定义钉在采纳上**：候选稿只是提案，玩家否决即不成立（玩家是作者，作者否决不构成已叙述事实）——与"叙述即公开"同一条铁律，账本只收玩家最终采纳的那一份正文。

## 四、对话 · NPC 主动 · 玩家引导（引擎侧留存）

> 编排决策（何时专注、谁主动联系、给什么建议）全归三章导演；本章只留引擎必须持有或执行的部分。

### M5 · 选择分支与关系值结算（暂缓二期）

> **状态**：本机制与〇③ 抽象属性轴一起暂缓，二期再设计。v1 不实现关系轴数值结算；关系进展由导演按事件流叙述体现，面板无数值栏。以下为二期设计基线，保留供后续设计。

**一句话**：选择分支结算关系轴数值，变化原因自动留痕。

- **触发**：王蓉求助修电脑，帮/拒。
- **结算落点**：分支判定 → 命中〇③ 关系轴（标"记因"的轴）→ 数值更新，并自动在 ② 落一条账（谁 · 因何 · 影响谁 · ±多少）——日后王蓉态度变了，系统与玩家对得上账。

### M8 · 节奏档 · 引擎侧执行

**一句话**：叙事节奏 = 玩家可调的节奏档（档位值存〇章叙述预设）；导演在档内判戏，本条只留引擎必须执行的机械部分。

- **档位归玩家**：快节奏 / 慢节奏等档位是玩家的偏好输入——设置入口随时自选、随时可改，默认档由内容包给、玩家可覆盖；导演"节奏感"的唯一依据 = 玩家当前所选档位。
- **导演在档内排戏**：档位框节奏幅度（快 = 事件流速高、琐碎日常少；慢 = 细描日常、多驻留细节）；对话聚焦（"这段戏专注双人、事件缓发"）、放权快进等切换由导演按戏情判定——档位边界玩家划、档内切换导演判。
- **引擎侧执行**：① **事件暂停**——档内离场/偶遇/推进类戏份缓发，玩家出的题仍走流水线；位置覆写与时段编排在档内挂起，切出档后由导演决定是否补排；② **上下文收敛**——装配收敛到「当前场景可感知 + 对话对象 + 关键历史状态」，世界其余留在账本（分层检索）。
- **关联**：对话回合时钟冻结（M20）；放权快进 = 玩家声明跳时 + 导演编排时段戏（该时段世界发生了什么由导演排、说书人成文，时间推进随玩家声明跳时结算，见 M20）。

### M12 · NPC 主动联系 · 主动登门

**一句话**：NPC 主动联系 = 导演的**主动性排戏开关**——当前没有更重要的事件需求时，安排 NPC 主动找上玩家，作为在场戏走正常流水线。

- **触发时机（导演判）**：当前没有重要事件需求（主链无事可推、玩家没在追事、或关系线 / 目标该冒头）→ 导演挑 NPC、挑由头安排她主动登门。节奏该推（M8）、目标待推进（M14）是主要排戏依据；NPC 卡的"主动倾向"是人设素材。
- **呈现 = 在场戏，不是离线消息**：本作没有"离线时段"——时钟只在玩家输入回合推进（M20），玩家不在场事件流不留账，NPC 发不出"你不在时"的消息。主动找你 = 导演在当前回合排一场**她找上你**的戏（登门 / 路遇 / 同场偶遇 / 托人带话），由说书人成文、走正常流水线（质检 → 候选区 → 玩家采纳才落账）；可及性由导演按空间常识照应（NPC 须能出现在你的地点或邻接点）。
- **决策归属**：谁主动、何时、以什么由头与方式 = 导演按节奏档 + 人设 + 目标台账排；有 has_actor 的 NPC 遇深抉择可派其 Actor（见三章）。

### M14 · 剧情目标（主线载体，2026-09-07 取代开放钩子台账）

**一句话**：玩家在导演窗口设立剧情方向（大目标=主线 / 小目标=支线），编剧写作时向目标自然引导，审计在采纳时判定目标完成。

- **设立**：玩家与导演 OOC 商量 → 导演回 set_goal action（text / kind: big|small / subject? / big_goal_id? / npc_id?）→ 玩家确认 → 落 save.goals；废弃同理（status: abandoned）。活动目标上限 6 条。
- **归属者（subject）**：目标不限于玩家——`subject` 可为 `player`（主角自己的目标）或某 `npc_id`（该 NPC 的目标，玩家与导演讨论时替 NPC 设立，如「王蓉想让主角答应下周跟她一起去接货」）。NPC 目标由该 NPC 在戏里主动推进：在场 → 自然提及（试探/欲言又止）；不在场 → 主动来找玩家（登门/路遇/托人带话）。
- **引导（编剧职责，非引擎机制）**：剧情目标块置于编剧工作单预设段之后（不可裁块）。编剧本回须向目标自然推进——NPC 提起线索、机会现前、冲突冒头；一次只推进一小步，禁止一轮内生硬给出全部结果；目标之外的自由展开不受限制。
- **完成判定（审计）**：采纳时审计按已采纳正文判定目标是否实现——小目标 = 当事达成；大目标 = 关键真相/冲突已解决。只推进未达成的不填（推进由编剧纪律负责，审计只判终点）。**推进 ≠ 完成**：目标 NPC 提及/推进目标（王蓉提起接货）只是推进，只有正文里目标所述之事真正发生（玩家答应了）才判完成。判定后目标置 done，记 done_at。
- **可见性**：玩家侧栏"剧情目标"列表（active 目标实时展示，大目标标注主线）。
- **玩家是作者**：目标由玩家设立与废弃，引擎不自动生成小目标、不自动提取承诺；"答应过什么"类即时问答走导演窗口答疑（查事件流）。
- **钩子台账已废弃（2026-09-07 拍板）**：原"审计自动提取承诺/未了事"不行——玩家看不到、不主动产生剧情，实际未发挥作用。其"内容包预置主线种子"的扩展方向一并废止，主线即玩家主动设立的大目标。
