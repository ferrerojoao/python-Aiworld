# AIWorld —— AI 文字世界引擎 · 策划文档（GDD）

> 对齐：REQ 机制需求清单正本（当前口径）
> 日期：2026-09-03
> 定位：**本地 Web 的"轻量 AI 活世界"文字角色扮演引擎** —— 玩家用自然语言与一个持续演化的世界互动；世界状态收敛在一本"账本"里，由无状态 Agent 工人轮流驱动。
> 基准：本文只陈述已采用的设计，机制权威源 = `REQ-机制需求清单-AIWorld.md`（本文不重复机制细则，只讲策划口径与体验）。

---

## 0. 一句话定位

一个跑在本地的 **AI 文字世界扮演引擎**：玩家通过浏览器输入动作 / 对话 / 跳时，系统以**事件流账本**为唯一真相，由**编剧 / Actor / 质检员 / 世界审计**四个 Agent 协作（加规则段，2026-09-05 导演与说书人合并为编剧），把玩家每一句输入变成一段正文。正文**只有玩家采纳后才成为世界事实**——玩家是这个世界的作者。

**与 Tavern 式纯扮演的区别**：世界不止回话，它**记得**（账本累积）、**会变**（关系与经历演化）、**有边界**（NPC 只说自己知道的事）。

**与 BRING 式全时模拟的区别**：世界**不后台全模拟**——结算只发生在玩家可感知的叙述里，其余一切靠查询与推断。省资源是设计铁律，不是工程妥协。

## 1. 项目目标与边界

### 1.1 目标
1. 让玩家**只靠自然语言**扮演：动作 / 对话 / 探索 / 社交，全部口语化表达，无指令语法负担。
2. 世界**持续演化且有记忆**：今天埋下的承诺、结下的关系，几天后会以"世界里的变化"回到玩家面前。
3. NPC **像人一样活着**：有自己的日程、记忆、秘密和判断；记得玩家帮过他，也会对玩家守口如瓶。
4. 玩家是**作者**：对正文不满意可以重掷，对世界的账可以纠错，一切以"玩家确认"为准。
5. 全程**本地可控**：OpenAI 兼容接口（DeepSeek / Qwen / Ollama 皆可），成本与隐私自持。
6. **可换世界**：世界观 / NPC / 场景 / 数值轴（二期）都是内容包，换包即换世界；叙述预设是全局通用配置，不随世界包走。

### 1.2 边界（明确不做）
- 不做实时多人在线世界；单机单玩家。
- 不做后台全时世界演化（BRING 式 60s tick）；世界只在玩家回合内推进。
- 不做向量语义检索（二期）。
- 不做复杂战斗系统；数值/关系轴一期先预留、二期再设计，不做回合制战斗框架。
- 不做自动世界生成；世界由作者编辑，提供导入与校验工具。
- 不做移动端原生 App（浏览器自适应即可）。

## 2. 玩家体验与核心循环

### 2.1 玩家视角的一天（体验示例）

> 玩家打开 `http://127.0.0.1:8765`，进入「青石镇」存档。界面左侧是当前场景与在场 NPC，右侧是状态面板，主区是正文流。
>
> 玩家输入：`去校门口找朱明，问问他昨天为什么跟人打架。`
>
> 系统处理：
> 1. 引擎先走规则段（尽量零 LLM）：解析目的地（由人推位置 → 按最后位置与人格隐含判断他在哪一带）→ 结算耗时、推时钟 → 到达校门口 → 查出在场者。
> 2. **导演**把"移动 + 对话"当**同一场戏**一次判定：朱明在，且对话涉他的密（昨晚打架）——判断这触发**深抉择**，他不愿提。
> 3. 朱明有 Actor → 派他的 **Actor** 以"他自己知道的"为界隔离决策：打哈哈、转移话题。
> 4. **编剧**把这次戏当成"移动 + 对话"的同一场戏，脑中排好节拍（先到、撞见、寒暄、回避打架）后直接成文。
> 5. 正文由编剧按当前文风把这层"含糊带过"的戏写成——深抉择已先由 Actor 隔离决定、按决策落笔。
> 6. **质检员**核对：有没有漏出朱明不该知道的来源、文风是否一致、有没有禁用词。
> 7. 正文送达玩家——**还没落账**。玩家可以采纳（世界往前走），也可以换说法 / 换走向 / 告诉导演哪里不对（重掷/抽卡）；每次重掷会生成一份新候选，旧版本保留供比较。
> 8. 玩家采纳 → 这条戏**原子落账**成史实，时钟与在场者更新；提交后结算随即扫到"玩家问打架未果"——若这正踩着玩家设立的目标（如"查明打架真相"），审计判其推进/完成，编剧后续回合继续向目标引导。

### 2.2 核心循环

```
   玩家输入 ──→ ① 规则段（移动/跳时/声明：尽量低 LLM，规则优先）
                    │
                    ▼
             ② 导演判定（每回合必经）
              ├─ 已成文输入 → 核对节奏 → 采纳
              ├─ 不完整输入 → 判缺什么、取账本补料
              ├─ 空泛输入 → 按节奏档自由编排
              └─ 撞深抉择 → 派 Actor 隔离决策 ──→ 决策块回流
                    │
                    ▼
             ③ 编剧成文（唯一正文笔，脑中排节拍后直接成稿）
                    │
                    ▼
             ④ 质检员把关（文风/泄漏/禁用词）
                    │
                    ▼
             ⑤ 候选区送达玩家（可多版本并存）──选择采纳/唯一候选继续输入──→ 原子落账（成史实）
                              ├─重掷/抽卡──→ 新增候选版本（账本无痕）
                              └─放弃──→ 清理全部候选（账本无痕）

   提交后结算（采纳时同步）：关系结算（二期）/ 目标完成判定 / 生命周期扫描
```

### 2.3 回合（Turn）模型

- **一次玩家输入 = 一个回合**。回合包含正文与**全部账本副作用**（时钟推进 / 位置变化事件 / 经历 / 私密名单初值），它们作为一个事务整体存在。
- 输入里可用**行内导演指令**：`((...))` 包裹的片段是给编剧的本回合写作要求（如"((加强动作描写)) 我冲上去"），引擎剥离后单独递给编剧执行——不进正文、不算台词、不落账本；重掷时沿用。临时要求用 `((...))`，长期文风走设置里的编剧准则。
- 正文送达玩家后进入**候选区**：质检只负责"够格呈现"，**玩家采纳那一刻才落账成史实**。
- 玩家可对候选区做几件事：**采纳**（从候选版本中选一份原子提交，回合闭环）、**重掷/抽卡**（生成新的候选版本，旧版本全部保留供比较）、**放弃**（丢弃整个回合候选，不落账）、**先开导演窗口商量**再回来定夺；若当前只有一份候选，**下一次直接输入会默认采纳它**并进入新回合；若有多份候选，玩家需先选择采纳哪一份。
- 候选稿只是提案——玩家否决即不成立。世界**只记录玩家最终采纳的那一份**；采纳后未选中的候选一并清理。

### 2.4 世界的"节奏感"

- 快 / 慢节奏是**玩家偏好档**（设置里随时改），默认由内容包给。
- 导演判戏只认玩家当前所选档位：快档事件流速高、琐碎少；慢档细描日常、多驻留。
- 正文的"怎么写"（文风 / 描写方式 / 禁用词）由**叙述预设**约束，是执行规则、不参与判戏。

## 3. 世界的真相：账本

### 3.1 账本构成（物理落库四块 + 运行态一块）

| 块 | 内容 | 谁写 |
|---|---|---|
| **事件流** | 玩家采纳后的正文成事件条目：时间 · 位置 · 在场者 · 公开或私密名单（known_by）· 正文。**唯一运行时真相** | 玩家采纳时引擎落账 |
| **实体档案** | NPC 三分类数据（人物卡 / 经历 / 抽象属性〔二期预留〕）+ 生命周期位（active / retired） | 作者预制 + 引擎随回合累积 |
| **世界设定** | 作者直写的世界背景，**两级**：**概要**（硬规则+基调，人手一份常驻）+ **世界书**（详细设定条目，导演点名才展开） | 作者内容包 |
| **元配置** | 全局叙述预设（编剧准则单框）+ 玩家设置 | 全局默认 + 玩家设置 |
| **引擎运行态** | 世界钟指针、剧情目标台账（M14） | 引擎内部 |

### 3.2 不落库的东西（全是查询或推导）

位置、在场者、公开 / 秘密、"谁记得什么"——**都没有独立存储**，由事件流查询直接得出。NPC 的"此刻在哪"是事件推导 + 日程推断；"王蓉知不知道那件事"是引用权查询。世界不为这些建表，账本就不膨胀。

### 3.3 读取规则（切片）

任何角色开口前，引擎按他的视角现配"本轮工作单"：
- **可引用全集** = 世界概要 ∪ 公开事件条目 ∪ {私密条目 | 名单含他} ∪ {本场点名展开的世界书条目}。概要常驻每份工作单；世界书默认缺席，导演这场戏点名才展开全文（细则 §4.4）。
- 幕后注与导演意图**永不进任何切片**——只有"叙述成戏"后它们才变成事件、进入引用域。
- Agent 全是**无状态工人**：开工前配工作单，干完写回，转身即忘。记忆永远在账本，不在 Agent 脑子里。

## 4. 数据契约（策划口径）

### 4.1 NPC 档案 · 三分类

| 类 | 内容 | 谁来写 | 生命周期 |
|---|---|---|---|
| **① 人物卡** | 外貌 / **人格**（性格+特点+说话风格+前史+身份定位合一格）+ 幕后注（可选私区，仅导演可读）+ 自知隐秘 + 引擎字段（has_actor 初值、听域 region、is_player） | 作者开局预制；增厚走**补卡事务**（玩家口述 → 导演拟稿 → 一致性核对 → 玩家确认） | 开局后**只读**（**主角卡同列**：`is_player` 标记，不可删除、不可退场） |
| **② 经历** | 玩家采纳后的事迹规则化拼接（时间+地点+谁干了什么+在场者+定性附注）+ 当前状态缓存 | 引擎随回合追加 | **只增不改** |
| **③ 抽象属性** | 内容包按题材声明的数值轴（好感 / 信任 / 力量…）：{范围 / 初值 / 可见性 / 归属实体}；挂玩家或 NPC 实例。**二期启用** | 引擎每回合结算覆盖（二期） | **覆盖** |

- 内容包一个轴都不声明时，世界照常运转——关系进展由导演按事件流叙述体现，面板无数值栏（数值只是可选精度）。
- 关系轴标"记因"的，每次变化自动在 ② 落一条账（谁 · 因何 · 影响谁 · ±多少），因果全程可回溯（二期实现）。

### 4.2 秘密 · 叙述即公开（玩家视角）

- 玩家在场发生的事，叙述后**默认公开**——镇上人传得开，NPC 记得住（校门口打架全镇可闻）。但**可引 ≠ 会说**，编剧守一条总纲：**角色不是你**——案头资料角色本人并不知道，角色只说他自己经历过、来历该知道、或被人告诉过的事。所以问路的外乡人不会随口聊起一周前的镇上斗殴；你在青石镇的旧事到了千里外的城市也没人知道（轰动的大事可以传成风闻）；没档案的路人只知眼前可见；幕后注与私密更不会从不该知道的人嘴里漏出来。
- **NPC 的知识有机械清单（已知集）**：装配时为每个在场 NPC 算好"他知道什么" = 亲历 + 名单内私密 + 听域内公开事件，写手和质检**照单办事**。事件发生地由场景表 `region:xxx` 标签声明；NPC 耳朵听到哪个区域，由**人物卡自己的 `region:xxx` 标签**（来属地/听域）决定，没填就按他的亲历推断——新手村的英雄事迹，到了王都的守卫耳里就是查无此事，你自报家门他只会当你是吹牛的外乡人；你在王都当街做了轰动大事，全城 NPC 自动风闻，不用谁打新闻标签；一个刚来青石镇出差的外地人，活动场景在青石镇，但听域还是家乡，你在这里的打架名声他闻所未闻。剧情顺笔的一次性布景（无名巷子、今晚的草地）不进任何人的风闻通道——在场者算亲历，旁人要么当时在场、要么听你亲口说。单区域世界不打标签，行为不变。
- 私下发生的事（按内容判：外人会不会知道这事发生过，不单看地点）落库时由导演挂**私密名单**（known_by = 在场知情者），名单外 NPC 查不到。
- **秘密 = 还没被叙述出来的真相**：作者底牌藏在幕后注、NPC 心里藏着导演注入的记忆——玩家撞破 = 排一场戏，真相首成正文、落新事件，从此大家知道。
- 玩家对事件公开 / 私密判错了可以**改判**（导演窗口）：让某件误公开的事收回私密，或让某件误私密的事公开。改判是补救行为——公开期间传开的部分逻辑上收不回，玩家选择改判即接受这个代价（名单由导演直接给定，引擎不检索起草）。
- 官宣这类"世界公开化"**靠叙述不靠翻旧账**：排一场公开戏，全镇自此知道"他们在一起"；当年私密细节保持私密。

### 4.3 叙述预设（全局两个大框）

预设是**全局通用配置**，不随世界资产包走。一个创作框 + 一个禁令框：

- **编剧准则**：给编剧/质检看的创作与写作要求，例如排戏规则、文风、描写方式、禁用词等自然语言描述（2026-09-05 由导演准则与说书人预设两框合一）。
- **禁用词表**：不许出现在正文的词（逗号分隔），仅质检规则层硬拦使用。

编剧按编剧准则成文，质检按同一块内容做文风核对并执行禁用词硬拦。

### 4.4 世界设定 · 两级引用

- **世界概要**：几句话框定时代 / 地点 / 基调 + **硬规则**。每份工作单人手一份、永不裁剪——LLM 靠它打底、凭自身知识补足细节。上古卷轴版 = 开头那几句"天际省"：框架框定后，细节随意发挥。
- **世界书**：作者把详细设定写成条目（`id · 标签 · 摘要 · 正文`），默认不塞给任何人。每回合引擎按当前情境（在哪个场景 / 跟谁 / 聊什么）把**可能相关的条目摘要**列给编剧；这场戏要用就按此设定写。编剧不会被要求通读世界书——他只看到递到眼前的候选，token 只在候选进入时付。
- 两条铁律：**硬规则只进概要**（不查书的人也不能写错世界观）；**世界书只读**（即兴补出的世界细节走叙述、落事件流，不回写）。

## 5. 工人阵容（2026-09-05 合并：导演 + 说书人 → 编剧）

> 源头问题：任何"全知大脑"代笔都可能说出不该知道的话。解法 = **决策可多脑**（编剧拿主意、深抉择派 Actor）、**文字唯一 + 必经质检**（编剧动笔、质检把关）。

| 工人 | 干什么 | 每回合 |
|---|---|---|
| **编剧**（导演+说书人合一） | 判断本回合"戏的走向"，**脑中排节拍后直接写成正文**（按叙述预设成稿）；深抉择上缴 actor_questions，拿回 Actor 决策后按决策成文 | 必经 1 次（深抉择 2 次） |
| **NPC Actor** | 有 has_actor 的 NPC 撞上**深抉择**（内心判断 / 涉密反应 / 是否信任）时，以"他自己知道什么"为界隔离决策 | 触发才上 |
| **质检员** | 必经前置文字关：文风核对（局部改写）/ 泄漏比对 / 禁用词硬拦。过稿才送达 | 必经 |
| **世界审计** | 采纳时提交后结算：时间推进同步 / 关系结算（二期）/ 目标完成判定 / 生命周期扫描 | 采纳时同步 |

### 5.1 谁用 Agent（has_actor 怎么定）

- 作者内容包**预标重要 NPC**；即兴角色转正（玩家深聊）时决定初值。
- 档位**单向升档**：角色戏份变重（关系升温 / 连续深聊 / 目标挂账）时导演升格配 Actor。
- 玩家可在导演窗口**点名某 NPC 必须用 Agent**，随时点名 / 取消。
- 关键：Actor 是**储备不是常驻**——日常浅反应（脸红 / 低头 / 招呼）导演照旧代笔，只有撞上深抉择那一刻才派活；纯功能性发声（招呼 / 跑腿）走话术模板，尽量零 LLM。

### 5.2 角色的来与去（玩家可感知）

- **即兴角色**：AI 可能在现场捏出一个没档案的角色（街角的老乞丐）。他没档案 = 他只知道眼前能看见的（可感知区），说不出任何"他本不该知道"的事。玩家深聊他 → **转正仪式**：现场建档（含他登场前的见闻，立为私密条目）、决定是否配 Actor，正式成为世界一员。
- **升格**：路人角色戏份变重（开始恋爱 / 深抉择变多）→ 导演给他升格配 Actor、补厚人物卡——正文里他就越来越"像自己"。
- **退场**：角色死亡 / 永久离开 → 世界审计扫到终态事件 → 标记 retired。他的卡、经历、欠你的情**全部保留**在账本里；未完成的目标由玩家定夺（继续追 / 废弃）。他人照样能回忆他——事件流作为真相层，与本人状态无关。

### 5.3 深抉择 vs 浅反应（玩家可感知的差别）

浅反应是表象（脸红、低头、日常对话）——编剧直接写。深抉择是内心水区（是否背叛你、要不要说出真相）——派 Actor 用他自己的记忆与判断决定，编剧不替他拿主意。

## 6. 一回合怎么走（总流程）

### 6.1 输入路由（玩家的话分四类）

| 玩家输入 | 处理 | LLM |
|---|---|---|
| 对话 / 行动 / 探索 | 上主链（编剧 → 质检） | 全链 |
| 移动（"去网吧"） | 规则段：解析目的地 → 可达 / 耗时 / 推钟 → 到达 → 在场者 → 场景描述 | 尽量零 LLM，规则优先 |
| 跳时（"等到晚上"） | 规则段：推钟 + 导演排时段简报 | 部分 |
| 状态查询 / OOC | 并入主链由编剧答（2026-09-05：query 旁路已删，UI 已展示时钟/场景/在场） | 主链 |

- **混合句**（"去网吧找朱明，问他打架的事"）：引擎先跑移动规则段作为导演输入，导演把"先到后聊"当**同一场戏一次判定**，正文一次成稿。
- **场景描述**：常规到达 = 模板底稿（引擎拼，尽量零 LLM）；首次到达新地点 / 剧情舞台 / 特殊氛围才由编剧专门写。

### 6.2 送达之后：候选区（玩家的作者权）

| 玩家操作 | 含义 | 账本 |
|---|---|---|
| **采纳** | 从候选版本中选一份，这版就是发生的事 | 原子提交，成史实；提交后清理其余候选 |
| **继续输入** | 若只有一份候选，直接提交下一条指令等于先采纳它再开新回合；若有多份候选，需先选择采纳哪一份 | 选中的候选先原子提交，再走新回合 |
| **换说法** | 戏不变，只重跑编剧换写法，生成一份新候选 | 账本零写入，多版本并存 |
| **换走向** | 反应不对，导演重排整场戏，生成一份新候选 | 账本零写入，多版本并存 |
| **定向重掷** | 告诉导演哪里不对（"别让他这么快坦白"），按意见改，生成一份新候选 | 账本零写入，多版本并存 |
| **放弃** | 不要这个回合了 | 当前回合全部候选一并清理，账本无痕 |

- 采纳后反悔 = 走导演窗口补救（圆场戏 / 覆写 / 改判），与候选区重掷是两条轨。

### 6.3 导演窗口（戏外工作台）

玩家主动开启，窗口里全是戏外话（玩家说了 ≠ 主角说了）。四件事：

1. **求建议**：导演扫剧情目标 + 当前张力，给 2~3 个建议（收尾型 + 推动型）。
2. **答疑**：玩家忘事 → 只读账本简略回答。
3. **剧情讨论**：商量走向 → 聊定后导演给简略输入建议，玩家复制进正文框执行。
4. **幕后事务**：改账本的操作——静默覆写（"朱明明天去夏令营"）、记忆注入、事件访问改判、剧情目标（设立/废弃）。一切在玩家确认后落账。（人物卡 / Actor 档位 / 转正 / 场景注册改由世界工作台直接编辑。）

## 7. 时间与空间（玩家体感）

### 7.1 时间怎么走

- 时钟只在你**输入**时走：你说"等到中午"就走；你修电脑没提时间就按默认耗时走；审计按"经历了什么"估这场戏时长（聊天几分钟、睡觉八小时），正文明确说到点了（"到了晚上八点"）就直接对钟，不被台词里随口提到的时间词带偏——"明天见"只是说说，不是过完了今晚。**离线不推进**——世界停在你说再见那一刻。
- **起点由作者设定**：每个世界在内容包里声明开局时刻（世界工作台概览页可改）；新建存档与重置存档都从该时刻开始。
- 对话回合时钟冻结；纯闲聊不推时间。
- 位置（"朱明 14:00 在网吧"）由事件流事件推导，在**结算当场**写入事件；旧事件过期后降级为推断素材。

### 7.2 空间怎么走

- 地点 = **预置为主**（内容包写死常驻地点），玩家走进包外地点（"街角新开的奶茶店"）→ 当场注册、之后可复用。
- 场景描述惰性生成：到了才拼；在场者 = 查询该地点最近事件推导出的实体集合。
- 玩家一句"朱明在家睡觉"可以**覆写**世界状态（事实道：立即生效）；"为什么在家"的理由（故事道）等他被撞见被追问才现编，说出口即落账。覆写撞上已有见证事实（先前有人目击他在网吧）时走导演窗口商量补救（追溯修正 / 叙事补圆 / 覆写三选一）。

### 7.3 没大事推的时候：NPC 会主动找你

- 没有"上线 / 回城"，也没有"离线时段"——时钟只在你输入时走（7.1），你不在场事件流就不落账，NPC 发不出"你不在时"的消息，也没有收件箱等你查收。
- NPC 主动找你是**编剧的排戏手段**：编剧认为当前没有更重要的事件需求（主链无事可推、或你埋下的关系线 / 目标该冒头）→ 挑 NPC、挑由头，在当前回合排一场她**主动找上你**的戏——登门、路遇、托人带话都行，成文后照常走候选区，你采纳才落账。
- 所以"离线不推进"不是冷落你埋下的关系：你在时设立的目标与关系线，会在编剧挑的回合以"她主动来找你"的形式回到你面前——不用你追，世界自己回头找你。

## 8. 世界审计（提交后结算）

采纳时同步执行，玩家无感知：
- 时间推进同步（正文推了钟、账本跟上）。
- 关系结算（二期，③ 轴随 ② 经历刷新；v1 不执行）。
- 目标完成判定（M14：审计按已采纳正文判目标是否达成）。
- 生命周期扫描（死亡 / 永久离开 → retired）。（剧情一致性不做引擎仲裁——看得出矛盾的玩家自决，2026-09-05 拍板。）

v1 将审计放在采纳点串行完成，避免后台写与下一回合并发；若未来改异步，需加写锁/队列并保证幂等。

## 9. 内容包（换包即换世界）

一个世界目录 = 一套资产，作者离线编辑：

```
<world>/
├── world.json            # 元信息 + 世界概要（硬规则/基调/背景）+ 开局场景 start_scene + 开局时刻
├── lorebook.json         # 世界书：详细设定条目（可空；空 = 纯概要世界）
├── scenes.json           # 场景注册表：场景名（键即显示名）·别名·可感知区·消息域
├── npcs/                 # 每 NPC 一卡（外貌/人格/幕后注/自知隐秘/has_actor/听域）
│                         #   ↳ 主角也在这里：is_player 标一张，有且仅有一张、不可删除
├── axes.json             # ③ 抽象属性轴声明（题材级，可空；二期启用）
└── save.json + events.jsonl   # 运行账本（与资产同层：世界=存档，单一真相源）
```

作者写好一个包，引擎照单运转——角色在包里"是谁"，活成什么样由玩家与账本共同决定。**主角不是特例**：他与 NPC 用同一套字段、同一份文件，只是多一个"我是主角"的标记——所以世界工作台的人物页里看得见他，他也改不了名字之外的身份（删不掉、退不了场）。事件日志里记的是**名字**不是"玩家"，因此你中途换主角，旧日志照样自洽。

### 9.1 造世界：给最小种子，剩下的边玩边长

作者不必一次填满一张表。世界在开局后**始终可写**（世界工作台随时增删人物、场景、世界书），所以开头的正确做法是拿到一个能跑的最小世界，缺什么玩到那里再补：

- **空白种子**：只要世界名、主角名、一个开局场景，就有了一局——开场白留空时引擎写一句「主角来到开局场景。」，这是主角在本世界的第一条"我在哪"，不是占位符。
- **一句话草稿**：写一句前提（"九十年代县城高中暑假，我和同桌在镇上晃荡"），AI 铺出世界概要、开局白、3~5 个场景、2~4 个角色和几条世界书。**草稿先给你看，改过、点确认才落盘**——过不了引擎体检的包连磁盘都进不去。
- **体检随时点**：世界列表上每条都有校验结论，重复的场景 id、漏掉的主角卡、打错的开局场景都会当场列出来（此前是静默的）。
- **改哪里、存到哪，写在你眼前**：工作台各页直接改（没有"编辑模式"），所有改动直接保存到这个世界本身、即时生效——没有"模板"和"副本"两层，你正在玩的就是唯一的世界。主角卡数量这类硬伤存不进去（当场拦截），场景 id 打错字这类小病能存但会黄字提醒。想保住初始状态，开局时「导出资产包」把 zip 存到自己电脑；世界改坏了就删掉它、导入资产包，一个初始态的新世界就回来了。
- 世界名不再等于文件夹名：列表显示的是内容包里写的名字。

> 两类"转正"（正文里撞出来的新角色、走进去的包外地点）都落到**世界工作台**直接建档，不经过导演窗口——导演窗口只管改账本（覆写/记忆注入/访问改判/剧情目标/角色退场）。

## 10. 名词速查

| 名词 | 含义 |
|---|---|
| 账本 | 世界唯一真相：事件流 + 世界设定 + 实体档案 + 元配置 + 引擎运行态 |
| 事件条目 | 玩家采纳的一段正文，带时间/位置/在场者/公开或私密名单 |
| 世界概要 | 世界设定常驻层：几句话框定框架 + 硬规则，人手一份永不裁剪 |
| 世界书 | 世界设定按需层：详细设定条目（id/标签/摘要/正文），导演点名才展开全文 |
| known_by | 私密名单（可选）——只有名单里的人能引用这条 |
| 叙述即公开 | 玩家在场叙述的事件默认公开；秘密 = 还没叙述的真相 |
| 候选区 | 送达 → 采纳之间；区内正文与副作用未落账，可重掷 |
| 回合事务 | 一回合的正文 + 全部副作用一体提交/一体回滚 |
| 深抉择 | NPC 的内心水区，须派 Actor 隔离决策 |
| has_actor | NPC 是否配 Actor 的运行时档位（单向升档，玩家可点名） |
| 幕后注 | 人物卡私区，作者的牌，仅导演可读，永不进切片 |
| 自知隐秘 | ① 上的可选字段：该 NPC 自己知道的秘密（进他自己的 Actor 切片，2026-09-05 新增） |
| 剧情目标 | 玩家设立的剧情方向：大目标=主线/章节（≤2），小目标=支线/节拍（单父下 ≤3、未挂靠 ≤2）可挂到大目标下；编剧分层引导（大目标每回必推、小目标择机）、审计判完成，大目标闭合时其下子目标一并撤下（M14） |
| 叙述预设 | 全局通用配置，分“编剧准则”（创作+写作合一）“禁用词表”两块 |
| 导演窗口 | OOC 戏外工作台：求建议/答疑/剧情讨论/幕后事务 |
